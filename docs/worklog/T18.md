# T18 — M3's first rung: every status bit's setter, reader and battle-visibility

Branch `wt/t18-status-readers`. Docs/tools-only: byte-identical ROM is the
acceptance gate (step 6 cmp), src/ takes comments only.

## Baseline (step 1)

`python3 tools/inventory.py` printed, before any change:

```
statuses (M3): DERIVED-FROM-HEADERS: CollisionData.inc / BattleObject.inc named bits,
set/cleared directly by code (object_setFlag/object_setFlag2, strh Damage); nearest
per-status data table off_80209EC (data/dat01.s:155, 6 families x 6-7 records, record
stride 8, via sub_801A554 asm/asm00_2.s:22211) enumerates 6 status-effect families,
not the 69 bits -- verified 0/69
```

The 69 = 32 OBJECT_FLAGS_* (CollisionData.inc:3-34) + 32 OBJECT_FLAGS_2_* (:48-79)
+ 5 DAMAGE_* (BattleObject.inc:119-123). The regex only matches hex-valued
struct_consts, so the 7 decimal `*_BIT` shift constants (:36-42) are not rows.

## Method (steps 2-3)

Encoded as a site walker in tools/inventory.py (`_status_field_sites`), not by
hand. Setter = `bl object_setFlag1/object_setFlag2` (mask in r0; the helpers at
asm00_2.s:21607/21634 OR r0 into oCollisionData_ObjectFlags1/2) or an inline
orr/str to either field. Clearer = object_clearFlag/object_clearFlag2 or inline
bic/str. Reader = `bl object_getFlag/object_getFlag2` or a direct flags-field
`ldr/ldrh`, followed (within 14 lines, no intervening label/str/bl) by a
` tst`/`and`/`lsr` mask test whose mask register resolves to a constant.
Masks resolve from `ldr rX, lbl // =0xVAL`, `mov rX, #named/imm`, and the
`mov rX, #1; lsl rX, rX, #BITCONST` idiom; a multi-bit mask credits EVERY named
bit it covers (the 0xa000 BLIND|CONFUSED gate in MettaurDecideCheckStatusAndRow_
810A004, asm31.s:171395-171397, and the 0xc00 PARALYZED|FLINCHING reader at
asm00_2.s:12088 only exist as combined masks).

Two scanner bugs found and fixed while calibrating (each would have silently
moved a count):
1. The backward r0 resolver walked through an intervening `bl` and stole the
   previous call's mask (asm00_2.s:19656: the `=0xc00` load feeding
   object_clearFlag2 was being credited to the FOLLOWING object_setFlag1,
   giving flags1 0x800/0x400 a phantom +1 setter). Fix: stop at any `bl`.
2. `for v, n in consts.items()` inverted the tuple (int.startswith crash).

## Step 2 results (the three counts)

- **40/69 named bits written**: flags1 27/32, flags2 13/32, DAMAGE 0/5.
  flags1 never written: UNK_8 (0x80), UNK_26, UNK_28, UNK_29, UNK_30 — and
  FLINCHING is written only as part of the combined 0x400400 mask
  (asm00_2.s:18308) with UNDERSHIRT|USING_ACTION.
- **43/69 bits with >=1 reader**; **26 with none** (all 5 DAMAGE_* among them:
  ZERO named sites anywhere in asm/ — the damage-word bits are carried by the
  damage pipeline, not by named constants; they stay header-derived).
- 33 bits are both written and read.

Verified reader cites by eye (the two the verifier should re-open):
- BLIND: asm00_2.s:16861 — `bl object_getFlag` on the battle_findPlayer result,
  `ldr r1, // =0x2000; tst` (hides an object from a blind side).
- IMMOBILIZED: asm31.s:171385-171394 — `bl object_getFlag; mov r1,#1;
  lsl r1,#0xe; tst` (Mettaur RowCheck gate), then the `=0xa000` BLIND|CONFUSED
  gate that diverts to the Wander state.
Other strong ones: FROZEN asm00_2.s:16784 (bit-16 tst -> sprite_setColorShader),
PARALYZED|FLINCHING asm00_2.s:12088 (0xc00 tst).

## Step 3 — off_80209EC reconciliation

Decoded (one mask per family, asserted in code): 37 records, sizes 6,6,6,7,6,6;
record = ([0] flag2 mask u32, [4] hword duration, [6] CollisionData timer byte
offset):

| family (SEF high nibble) | label | flag2 mask | timer off | durations |
|---|---|---|---|---|
| 1 | byte_8020A04 | 0x8 | 0x1C | 90,120,150,4,300,600 |
| 2 | off_8020A34 | 0x80 | 0x1E | 480,720,960,4,300,600 |
| 3 | byte_8020A64 | 0x20 | 0x20 | 480,720,1200,4,300,600 |
| 4 | off_8020A94 | 0x40 | 0x22 | 2,60,120,4,300,600,30 |
| 5 | byte_8020ACC | 0x10000 | 0x2A | 150,150,150,4,300,600 |
| 6 | byte_8020AFC | 0x20000 | 0x2C | 150,150,150,4,300,600 |

Set difference BOTH ways, on distinct flag2 masks:
- Table-only (no direct named setter, reachable ONLY through sub_801A554):
  {0x40, 0x80, 0x10000, 0x20000} = **25 of the 37 records**.
- Directly-written flag2 masks outside the table:
  {0x1, 0x2, 0x4, 0x10, 0x100, 0x200, 0x4000, 0x8000, 0x40000, 0x80000,
  0x100000} (11 masks).
- Overlap: {0x8, 0x20} are both table masks and directly written.
- No table flag2 mask has a DIRECT reader; the observable read is on the
  flags1 status bit the object.s per-frame status tick propagates (measured:
  expiry of timer Unk_1e clears flags1 0x8000 + flag2 0x80, object.s:5438-5452;
  the blind tick clears flags1 0x2000, object.s:5509-5518; the tst-0x40 branch
  sets flags1 0x4000, object.s:5500-5508), so per-bit battle-visibility is
  judged on the flags1 bit.

## Step 5 — the three M3 candidates

1. **CONFUSED** — reader asm31.s:171395-171397 (Mettaur decision loop's
   0xa000 gate -> Wander, the only RNG roll that AI makes). Inflicting path:
   StatusEffectFinal 0x2X -> table family 2 -> flag2 0x80 + timer Unk_1e ->
   flags1 0x8000.
2. **BLIND** — reader asm00_2.s:16861 (sprite hidden from a blind side).
   Inflicter measured in full: asm00_2.s:11366-11368 writes BlindTimer 0x12c
   (=300 = family 3's index-4 record) + setFlag2 0x20.
3. **IMMOBILIZED** — reader asm31.s:171385-171394 (bit-14 gate in the same
   Mettaur loop). Inflicting path: StatusEffectFinal 0x4X -> family 4 (7
   records) -> flag2 0x40 + timer Unk_22 -> flags1 0x4000.

**Chip-id caveat (honest, not fitted):** the fixture hand (FIXTURE.md +13) can
carry any chip id, but the chips the existing rows actually fire (cannon row's
Cannon) inflict no status, and pinning WHICH chip id writes which
StatusEffectFinal value was out of reach in this budget — the
object_setCollisionStatusEffect1 callers are the asm31.s per-attack effect
routines (24120, 27756, 28187, 28298, 30138, 31361, 33745, 36893, 38452,
41724, 43380, 43805, 51863, ...), one per attack family, and mapping those to
ChipDataArr rows is M4 work. The candidates are therefore chosen by
reader-presence + table-reachability, with the inflicting byte each chip must
write named above. This is NOT the ticket's NEGATIVE exit — 23+ written bits
have readers; the walk found plenty.
