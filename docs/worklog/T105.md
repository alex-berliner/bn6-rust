# T105 worklog -- emotion face-selection gate

## Ticket
Port the emotion face-selection gate. src/emotion.rs:11 says only the calm
face is drawn; the ROM bank continues past it with one window per emotion,
which this build has no state to choose between yet.

The draw site is `drawEmotionWindow_801CDEC` (asm00_2.s:27646-27676), HUD
element 14, gated on r5[0xf] == 5 or 6 (skip) vs anything else (draw).

### Draw gate (cite asm00_2.s:27646-27676)
```
drawEmotionWindow_801CDEC:
    push {r4-r6,lr}
    ldrb r0, [r5,#0xf]        ; emotion byte (skip if 5 or 6)
    cmp r0, #6
    beq locret_801CE14
    cmp r0, #5
    beq locret_801CE14
    ldrb r4, [r5,#0x12]       ; X-slide counter (per emotion.rs comment)
    ...
```
r5 = eStruct2035280 (0x02035280, HUD struct base), so the emotion byte lives
at **0x0203528F**.

### Update routine (cite asm00_2.s:27278-27332)
`updateEmotionWindow_801CADC` reads `r5[0x17]` (state byte); if 0xff, loads
the emotion value from `GetBattleNaviStatsByte(0x29)`. It writes r5[0x15]
(prev emotion) but does NOT write r5[0xf] directly -- so a one-shot poke
to r5[0xf] (= 0x0203528F) at load is the ticket's described `+1NCP-style
poke` and is expected to persist through the 40-frame compare window.

`sub_801CC94` (asm00_2.s:27513-27569) CAN write r5[0xf] but only on a
specific RNG-driven path (`GetPositiveSignedRNGSecondary` gate, with an
r5[0x1d] counter precondition). Not expected to fire on a quiet 40-frame
battle window with no input -- but a live capture would confirm this;
without one I can only state the code path, not its timing.

## Choice of value
- 0 (calm): the existing draw path, baseline.
- 1 (next slot, "Full Synchro"): one of the easier reachable states; the
  ticket names this as a target. NOT in the 5-or-6 skip range.
- 2..4, 7..22: other face indices, out of scope for this ticket.

Picking value = 1 for the `emotion_syn_full` scenario (BATTLESTART + poke
to 0x0203528F = 1 + scripted none).

## Pass 4 (worker-zai, 2026-09-17): the real face-source chain, exporter v2, port

### Correction to the earlier recon: r5[0xf] is only the DRAW GATE, not the face

The face's identity does NOT come from 0x0203528F. Measured + read this pass:

- `drawEmotionWindow_801CDEC` reads r5[0xf] ONLY to skip values 5/6
  (asm/asm00_2.s:27648-27652); it then hands sub_802FE28 the same two fixed
  OAM words as always. The ART is what changes: `sub_801CB38` (asm00_2.s:
  27332-27464) re-uploads VRAM EVERY updater frame.
- `sub_801CB38`'s face slot comes from `sub_801E69C`/`sub_801E6A8`
  (asm00_2.s:30990-31050): `[r5,#0x48]` -> player BattleObject, alliance byte,
  then `possiblyGetBattleEmotion_8015B64` (asm00_2.s:15122-15174), which reads
  LIVE battle data:
  - `AIData.Unk_36 != 0` (u16 at AIData+0x36) -> enum 5, or `NaviStats.Mood
    == 0` (u8 at NaviStats+0xe) -> enum 5
  - else `AIData.Anger != 0` (u16 at AIData+0x34) -> enum 3
  - else `AIData.Unk_32 != 0` (u16 at AIData+0x32) -> enum 1
  - else `Mood == 0xff` -> enum 2, else 0
- enum -> face slot through `byte_801E6F4` (asm00_2.s:31044): [0,2,3,1,5,4].
  So **face slot 1 = ANGER** (AIData.Anger != 0), slot 2 = Unk_32, slot 3 =
  Mood 0xff. `byte_801E700` (transformation path) maps the BeastOut states to
  slots 5..9/20/22 -- which is where the 5/6 SKIP slots and the 15..19 aliases
  are actually consumed.
- Each face has its OWN palette: `lsl r0,r4,#5` over dword_872F114, 0x20
  bytes (asm00_2.s:27449-27452). The old single-palette asset was wrong for
  any non-calm face (face 1 would render in calm's colours).
- Player AIData base on this route = 0x02034080 (AGENT_GUIDE's
  JoypadPressed 0x020340a4 = base+0x24), so Anger = 0x020340B4.

### Why the row rides the chip route (STERILE+PAUSED), not REAL+BATTLESTART

The ticket sketched canon=REAL+BATTLESTART, but the subject is an OBJ: the
opening row's own numbers show the OBJ layer over that route diverges
(integrated total 18740 -- enemy materialize/palette assignment, declared
out of scope there). The 43 chip rows are the only route whose OBJ layer is
measured 0 (navi + HUD + emotion window both sides, F27b). So `emotion_syn`
= the `cannon` row's own recipe + the Anger poke + descriptor emotion=1.
STERILE is canon with two documented patches (battle never concludes); the
emotion chain is untouched by them. The calm no-poke negative is then
literally the cannon row: same recipe minus emotion, measured this session.
