## Statuses (M3) — verdict: no bit-indexed table exists (kept DERIVED-FROM-HEADERS, new trail)

Walked: `object_setCollisionStatusEffect1/2` (asm/asm00_2.s:21768/21776) just store the status
byte into `oCollisionData_StatusEffectBase/Final`. Consumer `sub_801A554`
(asm/asm00_2.s:22211–22230, plus 22251/22275 siblings) indexes the nearest per-status DATA table:
`off_80209EC` (**data/dat01.s:155**), **6 pointer words, pointer stride 4**, index =
`(StatusEffectFinal >> 4) - 1`; each pointer targets **records of stride 8** — [0] flag2 mask
word, [4] hword value, [6] CollisionData byte offset — 6–7 records per family
(byte_8020A04, off_8020A34, byte_8020A64, off_8020A94, byte_8020ACC, byte_8020AFC).
That table enumerates **6 status-effect families × timing variants**, not the 69 flag bits.
The 69 bits (OBJECT_FLAGS_*, OBJECT_FLAGS_2_*, DAMAGE_*) are set/cleared directly by code
(object_setFlag/object_setFlag2, strh to Damage) with no per-bit indirection. Mismatch vs 69
quantified: 6 families ≠ 69 bits; the bit rows stay header-derived.
