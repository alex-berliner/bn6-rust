`nm` on the current ELF (EWRAM data symbols):
```
02000000 D BATTLE_MARKER
02000000 D __ewram_data_start
02000100 d _RNvNtCsfOjFFig40ml_3agb9interrupt15INTERRUPT_TABLE
020001a8 d _RNvNtNtNtNtCsfOjFFig40ml_3agb7display6object7sprites16sprite_allocator13SPRITE_LOADER
020001f0 d _RNvNtNtNtCsfOjFFig40ml_3agb7display5tiled12vram_manager12VRAM_MANAGER
```

The current layout:
- `BATTLE_MARKER` (`[u32; 64]` = 256 B) owns `0x02000000..0x02000100`
- `INTERRUPT_TABLE` at `0x02000100` (right where `BATTLE_MARKER` ends)
- `SPRITE_LOADER` at `0x020001a8` (160 B past `BATTLE_MARKER` end)
- `VRAM_MANAGER` at `0x020001f0`
- TRC2 block lives at `BATTLE_MARKER[128..192]` = `0x02000080..0x020000C0`,
  fully inside the array, 0xE8 bytes below `SPRITE_LOADER`.

So the prose's warning that "TRC2 at 0x02000080 would overlap
`SPRITE_LOADER`" was true back in R6's day when `BATTLE_MARKER` was 128 B
and `SPRITE_LOADER` was right after it; it is **no longer true** on this
build (`SPRITE_LOADER` is now at 0x020001a8). The conclusion (the array
must stop exactly where it stops) is still right but the stated fact is
stale — the constraint is now `INTERRUPT_TABLE` at 0x02000100, not
`SPRITE_LOADER` at 0x02000080.

## Re-attestation (per ticket §4)

T28's verifier byte-confirmed all three tables out of the pinned ROM:
- `RecovHealBySubfamily_80EC870`: 9 u16 + 2 pad bytes at ROM offset
  0x0EC870. Body at :111133-111134 in the disassembly reads
  `0A 00 1E 00 32 00 50 00 78 00 96 00 C8 00 2C 01 E8 03 00 00` =
  `[10, 30, 50, 80, 120, 150, 200, 300, 1000]`. Matches `RECOV_HP`.
- `BarrierHpByType_8020B2C`: 8 rows × 6 bytes at ROM offset 0x020B2C.
  Rows :195-202 read `00 00 00 00 FF FF 0A 00 00 00 FF FF 1E 00 …
  01 00 64 00 FF FF` (stride 6 — first u16 of each row is 0, last u16 is
  -1 sentinel, the HP is the middle u16). `BARRIER_HP=10` ← row at
  offset +6; `BARR100_HP=100=0x64` ← row at offset +30; `BARR200_HP=200=0xC8`
  ← row at offset +36. Matches.
- `VulcanShotsBySubfamily_80EBFEC`: `.word 0xA050403` at ROM offset
  0x0EBFEC. Bytes `03 04 05 0A` little-endian = `[3, 4, 5, 10]`. Matches
  `VULCAN1_SHOTS=3, VULCAN2_SHOTS=4, VULCAN3_SHOTS=5, SUPRVULC_SHOTS=10`.

All three tables' values re-attest from ROM bytes. **Nothing unverified.**

The line-count pitfall: this project's `rustc` embeds panic-Location line
numbers into `.rodata` (one u32 per `panic!` site), so a comment edit that
adds or removes net lines shifts those line numbers by 1 per net line and
moves the ROM by 4 bytes per net line (2 bytes on this build, due to
relaxed u16 packing in a couple of sites — the first cut of this ticket
moved the ROM by exactly 2 bytes for +3 net lines and `cmp -l` reported
them at offsets 174373 and 302533, both byte +1; balancing the line count
zeroed the delta). Net change vs main's `3ba1e91`: +24/-24 = 0.
`cmp -l` reports 0 differing bytes. ROM sha256 = main's 435daeaf…
