## The HP walk: canon or ours?

Looked for a canon routine that steps a displayed HP value over frames:

- `GetMaxAndCurHPForCurPETNavi_80010D4` (reference/bn6f/asm/asm00_0.s:1963-1980)
  is a pure accessor over NaviStats CurHP/MaxHP — no stepping.
- `asm00_1.s:12860` (dispatchBattleFsm_8009158 low-HP sound gate), `:16301`
  (sub_800A86E alive-actor loop) and `:16994` read `oBattleObject_HP` but never
  write a display value.
- `asm00_2.s:29913`'s HUD-tile neighbours are the cust-gauge chain
  (ClearCustGauge/SetCustGauge/AddToCustGauge_801DFB8), not HP.
- No `thumb_func_start` symbol matching Number/Digit/HP-walk; no `asr #3`/`#2`
  divide sites in the battle asm files.

**Conclusion: NEGATIVE on a canon cite.** Canon has no walk routine with its
own divisor/minimum-step that a static grep can find; the 8 and the 4 are our
fit to a measured capture (60→50 shows 55/51/50). They stay `provenance:
peeked` — measured off the running game, not canon — exactly as the pre-existing
comment recorded. They are now named `HP_WALK_DIVISOR` / `HP_WALK_MIN_STEP` in
src/hud.rs with that provenance and the negative-finding note.

## The backdrop wrap

`256 * 4` IS canon-derived: canon's own scroll counters
(`oBGScrollCBCounters`, `BGScrollCB_BG1Diagonal3to2Scroll`,
reference/bn6f/asm/asm00_0.s:3305-3321, steps `.equiv`'d at :3293-3295) run in
1/16-pixel units and the on-disk note at :3287-3291 records their 4096-count
modulus = 256 px (32x32-tile motif). Ours are quarter-pixel units (module doc),
so the same period is `256 * 4`. Named `BACKDROP_SCROLL_PERIOD_Q`,
`provenance: derived`, comment carries the cite.

## verify_rows

The coordinator's literal command (`--expect field:ui=0/0/40 ...`) does not
parse on this harness: `--only` matches plain check names (`check.name in
wanted`, tools/harness.py:3225-3229), so `field:ui=0/0/40` selects NOTHING and
verify_rows reports `DID NOT RUN (exit 0)`. The `:ui=` suffix is allowlist
notation, not --only notation. The same expectations run under plain row
names:

