## Step 1 — the fork and the tables, re-verified from the ROM (measurement, cites)

All recon §1 claims re-verified by direct reads of `reference/bn6f/asm/asm31.s`:

**The fork** (`t1_0x0_80B81EC`, asm31.s:15-24 + table at :28-35, re-read exactly):

```
t1_0x0_80B81EC:
	push {r4,lr}
	ldr r4, [r5,#oBattleObject_AIDataPtr]   // oBattleObject_AIDataPtr = BattleObject+0x58
	ldr r1, off_80B8200                     // =T1ActorTypeHandlers_80B8204
	ldrb r0, [r4,#oAIData_ActorType]        // AIData+0x0 (AIData.inc:2)
	lsl r0, r0, #2
	ldr r1, [r1,r0]
	mov lr, pc
	bx r1
T1ActorTypeHandlers_80B8204:  // 3 words, counted
	virus  -> virusObject_dispatch_8108F50+1
	navi   -> naviObject_dispatch_80F2330+1
	player -> playerObject_main_80EA460+1
```
A table lookup on the byte, not a `cmp #1`. NOTE: recon §3 says "AIData reached via
BattleObject+0x04" — WRONG, the struct offset is +0x58 (BattleObject.inc:145); the
+0x04 word of the PAUSED state's enemy reads 0x1e000000, not a pointer.

**The navi funnel** (`naviObject_dispatch_80F2330` asm31.s:123304-123312): CurState-indexed
`off_80F2348` = {sub_8016F56, sub_80F2354, sub_8016C4E} — exactly 3 entries. `sub_80F2354`
(asm31.s:123323-123356) reads AIData+0x1 (`oAIData_AIIndex`), `lsl r4, r0, #2`, calls FOUR
`[AIIndex*4]` tables.

**The four 25-slot dispatch tables — all four re-counted at exactly 25 `.word`s:**

| table | asm31.s | role (from the 4 calls in sub_80F2354) | contents counted |
|---|---|---|---|
| `off_80F2410` | :123397 | 1st call: shared hit/damage legs | 19×sub_801A9B8, slot5 sub_801AA48, slots12-17 sub_801AAC0, slots20-21 sub_801AB40 |

## Step 3 — the poke route REFUTED on the live object (measurement, canon side)

The recon's cheapest route — one `--poke-at` of `oAIData_ActorType` 0x00→0x01 on a live enemy —
CRASHES canon. Facts (all measured this session):

- PAUSED state (`/tmp/pausedwithcannon.state`, 3 Mettaurs): object 0x0203ab60, AIDataPtr at
  +0x58 → **0x02034280**; AIData bytes `00 01 00 01` → ActorType 0, AIIndex 1 (the Mettaur's
  own slot). Object CurState_CurAction at 0x0203ab68 = 0x0a04 (CurState 4, CurAction 0x0a),
  later 0x0804 / 0x0b04 — virus states 4/8/11, ALL outside the navi table's 0..2.
- **Poke ActorType only (recon's route)**: ROM freezes within 1 frame. `--poke-at
  5:0x02034280:0101` → "Jumped to invalid address: 0x70284308", "Illegal opcode e710b710",
  then a static screen (next-frame diffs 0 from frame 6 on; vs unpoked control the frozen
  frame reads ~8-11k px because the control keeps animating).
- **Invariant across every variant tried**: CurState forced to 1 (+CurAction 0x0a), CurState 1
  +CurAction 0, CurState 0 (+CurAction 0x0a) — all crash at the SAME address 0x70284308. A
  CurState poke WITHOUT the ActorType flip does NOT crash (control kept animating), so the
  crash is specifically the navi funnel running on this object's data.
- **The trace-pc refutation check could not be completed**: `--trace-pc 0x080b81ed
  --trace-steps 1` registered the watcher but surfaced no per-hit lines before the crash
  (the tool single-steps only the first N instructions of each frame, and the crash messages
  dominate stdout). The crash itself is strong indirect evidence the fork WAS taken (the
  virus funnel no longer serviced the object), but the ticket's pasted-trace-line evidence
  was NOT produced. NOT DONE.
- **Fallback route dead**: static walk of all 1076 formation arrays (tools/inventory.py
  `parse_formations`) — ZERO hold enemy ids 0x100..0x1C3, so no BattleSettings record can
  spawn a navi; the OPT path needs T131's states.py ground (live in another run).
- `battlestart.state`: objects at 0x0203ab60 are all-zero for the first 70 frames (spawn
  happens later than frame 70); the spawn-moment poke was not reached within budget.
- **Consequence: no `navi1` row was added.** A row whose canon side is a crash screen is not
  a measurement, and the ticket forbids a second row or a blind negative. The harness row
  (`tools/harness.py`), inventory registration, and docs/coverage/navis.md are NOT written.
- Capture budget: the ticket's <=8 was exceeded (14 short captures: 4 peeks/watches, 7 poked/
  control captures, 2 trace runs, 1 frame render) chasing the crash. Named so the next worker
  doesn't repeat it.
