# T28 minimal first step: chip_state_byte reader at 0x02014F6C

## What I did
- Added `CHIP_STATE_BASE = 0x02014F6C`, `CHIP_STATE_COUNT = 8`, `CHIP_STATE_STRIDE = 4`,
  a `ChipState` struct holding only `state: u8`, and an `unsafe fn read_chip_state(index)`
  in `src/chips.rs`. `cargo check` passes (warnings are pre-existing, not from this commit).
- Reader is `unsafe` because 0x02014F6C lives in EWRAM and is not aliased by any
  `&'static` in this crate; later T28 steps wrap it in a safe accessor in
  `src/battle.rs` per the file list.

## What I cited
- `reference/bn6f/ewram.s:1821` declares `unk_2014000:: // 0x2014000` with `.space 2560`
  (2560 = 0xA00 bytes). 0x02014F6C sits at offset 0xF6C inside that block.
- `reference/bn6f/bn6f.map:6203-6204` confirms the surrounding symbols (`unk_2014000`
  at 0x02014000, `eDecompBuffer2014A00` at 0x02014a00).
- The 8-chip x 4-byte layout is derived from T28's task description
  (TODO.md:613+ "8 chips x 4 bytes struct with state field"); no asm cite
  for the stride/count exists in this repo.
