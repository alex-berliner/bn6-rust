## Why the cherry-pick conflicts

`git cherry-pick 8495f6c` on current main produces:

```
CONFLICT (content): Merge conflict in src/actor.rs
CONFLICT (content): Merge conflict in src/battle.rs
CONFLICT (content): Merge conflict in docs/coverage/battle_full.md
CONFLICT (add/add):  Merge conflict in docs/worklog/T66.md
```

The src/actor.rs hunks are mutual exclusion: HEAD has `phase_arm_shadow: u8` and
`PHASE_ARM_FRAMES = 10` + `SENTINEL_FRAMES = 1`; 8495f6c wants to add `timer_holds_sentinel: bool`
and a single `TIMER_SENTINEL: u16 = 0xffff`. They occupy the same struct field, the same const
block, and the same export arm (`Action::Flinching` arm + Idle-branch logic). There is no
"merge" that preserves both — picking the export logic for one means rewriting the struct field
for the other.

The second commit (9aa7e26) is worklog-only and trivial in isolation, but its parent
`docs/worklog/T66.md` is already present on main (added at `1cac961`, the T66 PARTIAL TODO
marker — the same 140-line file). The add/add conflict is between T66's own worklog on its
branch and the SAME worklog already on main; resolving it as "ours"/"theirs" is a no-op.

The third commit (13623d0, verifier follow-up, comment-only) modifies lines that 8495f6c added
on wt/t66 — the `timer_holds_sentinel` doc string and the Timer bullet in `oracle_fields`.
Those lines don't exist on current main (replaced by `phase_arm_shadow` doc), so 13623d0's
context doesn't apply.
