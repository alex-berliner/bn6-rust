Worktree: wt/t161-fieldbg-regression (based 940ffa7).
T145's landing commit a0f8049 is the only src/ commit between 05eb8f9 and 36eea42 (the HEAD
the ticket was authored against). The only src/ change at HEAD=940ffa7 over 36eea42 is T152a
(merge 1950c68), which the ticket does not name. This worklog records the bisect.

## Result in one line

**BLOCKED.** T145 is the sole cause of the field-bg regression. The minimal subset of T145
that must be reverted to restore the 05eb8f9 pins includes either the spawn fork (KIND_NAVI in

navi-gunner (or breaking other guard rows). Restoration appears to need a different port
shape for T145; the ticket as stated is unsolvable by removal alone.

## Step 2 bisect

**Experiment 1: T145 fully reverted** (all src/ files + tools/harness.py to 05eb8f9^, src/navi.rs deleted).
field-bg1 3600/3600/40/174345, field-bg2 3600/3600/40/3600, field-bg3 380219/24906/40/405125 —
all THREE rows restore to T147-gate pins byte-identically. T152a's battle.rs changes alone
do not move field-bg pixels (when T145 is reverted). The T152a +480 contribution is only
visible with T145 present — it is an INTERACTION effect of the two commits' binary layout.

**Conclusion of Experiment 1**: T145 is the SOLE cause of the field-bg regression. Restoring
pins requires reverting T145 (in full or in part).

**Experiment 2: data-tables stub** (src/navi.rs reduced to just `profile_ai17()` and
`NaviProfile` struct — no THINK_TABLES/STRUCT1_VIRUS_PTRS/etc.). All other T145 changes
kept. Build OK. field-bg1 STILL 5760/5760/40/176505.

**Conclusion of Experiment 2**: the 189 lines of data tables in src/navi.rs are NOT the
cause. The cause is in the code changes (Style::Navi enum + matches + spawn fork).

**Experiment 3: spawn fork removed** (battle.rs's KIND_NAVI branch reverted to pre-T145
all-Mettaur path). All other T145 changes kept. Build OK. field-bg1 4800/4800/40/175545,
field-bg2 4800/4800/40/4800, field-bg3 380263/24906/40/405169.

**Conclusion of Experiment 3**: the spawn fork (KIND_NAVI branch) accounts for ~960 of the
2160 px delta on field-bg1/2. But removing it changes KIND_NAVI spawns to Mettaur art, which
moves navi-gunner (the navi row NEEDS the GUNNER asset for its rust side).

**Experiment 4: Style::Navi enum + matches removed** (src/ai.rs Style::Navi deleted,
src/objects.rs match arm reverted, src/battle.rs 3 matches reverted, spawn fork's
`ai::Style::Navi` reference replaced with `ai::Style::Gunner`). Build OK. Results:
- field-bg1 8160/8160/40/178905 (WORSE — +2400 from baseline)
- field-bg2 8160/8160/40/8160 (WORSE)
- field-bg3 380263/24906/40/405169 (unchanged)
- cursor 16241/3385/170/170163 (BROKEN — was 1/1/170)
- navi-gunner 2092176/38237/130/2247584 (unchanged)

**Conclusion of Experiment 4**: removing the Style::Navi enum CHANGES the enum's
in-memory representation, which alters data layout of all `ais: Vec<Ai>` and `style: Style`
fields. This breaks cursor (1 → 16241). The Style::Navi variant is structurally necessary
to the current AI/actor data layout.

## Step 3 what blocks restoration

Decomposing the regression:
- 960 px: spawn fork (battle.rs KIND_NAVI branch). Cannot remove without moving navi-gunner.
- 1200 px: Style::Navi enum + matches. Removing breaks cursor (data layout shift).
- 44 px (bg3 only): minor, possibly the Style::Navi in objects.rs.

There is no subset of T145 that fixes field-bg AND keeps navi-gunner, mettaur, cursor byte-
identical. The Style::Navi enum is structurally coupled to the spawn fork (both reference
the variant); neither can be cleanly reverted without collateral damage.

What WOULD fix this:
- A different port shape that puts the new slot's data in navi.rs without changing the Style
  enum (e.g., expose a u8 ai_index from profile_ai17, and dispatch via a single Style::Navi
  variant that reads the profile — but Style::Navi cannot be removed per Experiment 4).
- A regression-prevention commit BEFORE T145's data is laid out that pins the field-bg
  reading; T145's binary layout would then be measured against that pin. (Not in scope
  for T161.)

## Step 4 what was tried, dropped
- Reverting T145 fully → restores pins but loses navi-gunner (rejected, ticket constraint).
- Stubbing data tables → no effect on field-bg (data is not the cause, dropped).
- Removing only the spawn fork → 960 px improvement but navi-gunner spawns wrong art (dropped).
- Removing Style::Navi enum → breaks cursor 1→16241 (rejected, ticket constraint).
