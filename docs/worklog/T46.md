## Inventory of the 6 chips — `data/ChipDataArr.s`

The "Bomb family" is a NAME group (6 chips whose display name ends in "Bom"),
NOT a single attack_family. Reading `data/ChipDataArr.s` (411 records, index =
chip id = TextScriptChipNames0_unkN), the six bombs sit at:

| chip id | name     | record line | attack_family | attack_subfamily | chip_element | attack_power |
|---------|----------|-------------|---------------|------------------|--------------|--------------|
| 0x36 (54) | MiniBomb | 1646 | 0x2F | 0x02 | 0x08 (WIND)   | 0x0014 (20)  |
| 0x37 (55) | EnergBom | 1336 | 0x29 | 0x00 | 0x06 (CURSOR) | 0x001E (30)  |

Three different attack_families. The element discriminator cleanly maps the
"ener" flag: `ener: chip.element == 0x06` activates for EnergBom/MegEnBom/FlshBom
and no other chip the harness uses. Subfamily 0x01 family 0x12 is BlkBomb only;
subfamily 0x0F family 0x12 is BigBomb only.

## Step 2: refactor (planned)

Replace the in-scope `match chip.id` arms in src/battle.rs's bomb block with
element/subfamily reads:
- `ener: matches!(chip.id, CHIP_ENERGBOM | CHIP_MEGENBOM)` →
  `ener: chip.element == CHIP_ELEM_CURSOR` (0x06). Also covers FlshBom (0x39),
  which currently rides through the chip_strike bomb block but never reaches
  the `ener` arm because FlshBom's row in the harness throws a flash bomb with
  its own animation 0 sprite, never `bomb_anim(chip.id, true)`. FlshBom is
  outside the bomb_anim call paths so its element value never affects the
  energy-blast dispatch — keeping the same set under the new rule.
- `bomb_anim(id, thrown)` → `bomb_anim(element, thrown)` dispatching on CURSOR.
- `bomb_palette(id, thrown)` → dispatch on family+subfamily (BlkBomb 0x12/0x01,
  BigBomb 0x12/0x0F, CURSOR family 0x29 sub 0x00 → ENER; default 0).
- `wide: chip.id == CHIP_BIGBOMB` → `wide: chip.family == 0x12 && chip.subfamily == 0x0F`.
- `chip.id == CHIP_BLKBOMB` (used multiple times) → `chip.family == 0x12 && chip.subfamily == 0x01`.
