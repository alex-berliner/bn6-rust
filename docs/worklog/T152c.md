## What canon actually does (the cite)

`isBannerBusy_801E754` (reference/bn6f/asm/asm00_2.s:31105-31131), called from
`bannerSeqState04BannerWait_8008064` (asm00_1.s:10569). Returns:
- 0 (idle, BANNER_WAIT advances) when mask bit 15 (0x020352C0 & 0x8000) is clear
- 1 (record busy) when mask bit 15 is set AND record is not in idle state
- 2 (record idle, but mask still set) when byte_2036848 in {2,4} AND byte_2036840 == 4

The handler's `cmp r0, #0 / bne locret_80080D0` advances the sequencer ONLY
when r0 == 0 (mask bit clear). The 60-frame wait observed in battle_full's
own trace is the BANNER RECORD's lifecycle (spawned at BANNER_WAIT entry by
`spawnBannerRecord_801E792`, runs 60 updates, clears mask bit 15 when done)
— separate from the visual banner, which goes up 30 frames after window
close (BATTLE_START_AFTER_WINDOW = 30, `banner_at`) and stays up for
`banner::SCALE.len()` = 58 frames.

## The port

Add `banner_was_up: bool` to the Battle struct, set it at both banner spawn
sites (opening at :3671, end banners at :3361), and replace the SEQ_04
transition arm:

```rust
fn is_banner_idle(&self) -> bool {
    !self.hud_live || (self.banner.is_none() && self.banner_was_up)
}
```

`!self.hud_live` covers the end-of-battle teardown path (mask-bit-clear).
`self.banner.is_none() && self.banner_was_up` covers the opening banner
record-idle path: the visual banner rolls up to None after SCALE.len() = 58
frames, which is the proxy for the banner record's 60-frame idle lifetime.

## What regressed and why

The cursor 32-px movement is the timing slack between the visual banner
lifecycle and the canonical banner-record lifecycle:

- Old model: SEQ_04 → SEQ_08 at age 60 (rust frame 242). The fitted count
  matched the canonical banner-record's 60-frame lifetime.
- New model: SEQ_04 → SEQ_08 at age 85 (rust frame 267). The visual
  banner is delayed by `banner_at = 30` (BATTLE_START_AFTER_WINDOW: 30
  frames after window close, set at line 3114), goes up at SEQ_04 age 27,
  rolls up at age 85. The model waits for the visual roll-up, not the
  record idle (which our model has no analog for).

25-frame shift in the rust side's SEQ_04 release. The cursor test's 170-frame
comparison window covers this transition (rust k=234 vs rust k=259 after the
change), causing the visible 32-px diff. The other harness rows either don't
visit SEQ_04 (popup, mettaur) or compare windows that don't cover the
transition (opening 0..39, windowclose 0..39). The trace target
(battlestart_scripted) never consults the predicate (entry_park pins age,
no banner spawns).
