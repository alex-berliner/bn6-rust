## The mgba format (the close-NEGATIVE cite)

All from `tools/mgba_capture.c` (7ag-owned, off-limits, read-only):

- Header doc, `tools/mgba_capture.c:30-48`: "signed 16-bit interleaved PCM to `<dir>/frame.####.pcm` (one file per frame, same numbering as the video). No container, no resampling of our own."
- Write logic, `tools/mgba_capture.c:947-967`: `int16_t pcm[4096*2]` filled by `blip_read_samples(audio_left, pcm, avail, 1)` then `blip_read_samples(audio_right, pcm + 1, avail, 1)`, written with `fwrite(pcm, sizeof(int16_t) * 2, avail, pf)` — interleaved L/R, 4 bytes per pair, per-frame cap 4096 pairs.
- Source taps, `tools/mgba_capture.c:629-630`: `core->getAudioChannel(core, 0/1)` — the post-mix left/right bus (PSG + both DirectSound FIFOs already summed), not a per-voice tap.
- Rate caveat, `tools/mgba_capture.c:30-48` and `1082-1086`: mAVStream.audioRateChanged reports 65536 Hz but actual measured rate is ~96000 Hz; the run prints "do not trust that number". The `--rate` flag in the comparator is informational only (duration line) and does not enter the comparison.

## Acceptance (4/4 PASS on synthetic fixtures)

The harness-like results below come from four synthetic trees built on the
fly (`/tmp/aud_t95_*`). The fixture shapes (varying per-frame sample counts,
a max-range frame at 32767/-32768, an all-zero frame, a one-pair frame)
match what mgba's `--dump-audio` actually produces — variable frame length
capped at 4096, never zero except when the resampler really has nothing yet
(the boot-ramp artefact in `docs/coverage/audio-buster.md` §3).

| # | case | tool output | exit |
|---|---|---|---|
| 1 | identical A vs B | `total 0 differing samples over 8 frame pairs ... worst 0 differing samples at k=-1, first divergent none` | **0** |
| 2 | A vs mutated B (one sample +1 LSB) | `total 1 differing samples over 8 frame pairs ... worst 1 differing samples at k=2, first divergent k=2 frame_A=00002 frame_B=00002 sample_idx=4 channel=0 a=199 b=200` | **1** |
| 3 | A (8 frames) vs truncated B (6 frames) | per-frame pairs all sample-exact, then `SAMPLE-COUNT MISMATCH: A has 2 extra frame(s) past the common prefix (first [6, 7]); B has 0 (first [])`, total grows by the leftover sample count (6) | **1** |
| 4 | A (s16le) vs B (u8 same filenames) | per-frame byte-length mismatch lines, format/decode errors (file length not multiple of 4) | **1** |

The "PASS on identical" line shape (`0 / 0 / -1` per the ticket) is honoured:
total 0, worst 0, worst-index -1, first-divergent "none", exit 0.

## Design choices and dropped alternatives

1. **No resampling / no tolerance.** Sample-exact, full stop. The ticket's
   close-NEGATIVE clause "a tool that requires a tolerance to match
   canonical mgba output closes NEGATIVE" drove this; the `--rate` flag is
   purely for the duration line.
2. **Per-frame byte-length mismatch is a defect, not "skip this frame".**
   Mirrors how probe.py diff treats differing pixels: any nonzero residue is
   reported at the frame it lives in.
3. **Frame-count mismatch (one tree runs longer) is a defect, not "stop
   comparing".** probe.py diff stops on `FileNotFoundError` because the
   pixel-capture scenario is a known-prefix match. For audio, the ticket
   asks for "sample-count mismatch reported", so the tool detects the
   unpaired tail and adds each leftover frame's sample count to the total
   (so the residue is visible in the numbers, not just in a free-text line).
4. **Format flag defaults match mgba output.** A user can override
   `--bits`/`--channels`/`--format` to compare non-mgba dumps; the defaults
   (`s16le`, 16, 2) match mgba_capture.c so the comparator works on canonical
   dumps without flags.
5. **Decode errors are surfaced as a separate `format/decode errors` block**,
   not lumped into "differing samples". A file whose byte length is not a
   multiple of 4 (for s16le stereo) is NOT a "32740 LSBs of difference" —
   it's a "this file is not in the declared format" signal, and lumping them
   would let a format mismatch hide as a defect with the wrong magnitude.
6. **Per-frame output echoes probe.py diff's `k=N value` shape, with the
   global-index / channel / value-A / value-B / max-delta added** so the
   audio-side first-divergent-sample report is at least as informative as
   probe.py diff's per-pixel count. A verifier looking at the output can
   answer "where exactly does the audio first disagree" without rerunning
   with a different tool.

## Things I did NOT do

- I did not measure audio against a real mgba capture (the ticket is a
  pure-tools/ comparator; the next ticket will run it on real canon-vs-rust
  trees). The synthetic fixtures are deliberately shaped to cover: variable
  per-frame length, an all-zero frame, a max-range frame at the s16 limits,
  a one-pair frame, a one-sample mutation, a truncated B side, and a u8
  format-mismatch B side. If the M9 follow-up finds a defect shape that the
  synthetic set does not cover, that's a comparator change, not a
  methodology change.
- I did not touch `tools/mgba_capture.c` (7ag-owned, off-limits per ticket
  and per `tools/mgba_capture.c` git blame).
- I did not change `tools/audio_probe.py`; the two tools have different
  ergonomics (probe is the verify-scenario helper, diff is the comparator).
  A future ticket could collapse them; not this one's job.
- I did not add any rate-based resampling or alignment window. The
  comparator is sample-exact by design (NEGATIVE close clause).

## What the next worker should know

- `tools/audio_diff.py` is the M9 comparator. It takes two trees of
  `frame.NNNNN.pcm`, compares them sample-exactly, and exits 0 only on
  perfect match (per-frame sample count AND per-sample value AND no
  leftover frames).
- The defaults (`--format s16le --bits 16 --channels 2`) match
  `tools/mgba_capture.c --dump-audio`. Override only for non-mgba dumps.
- `--rate` is display-only; the comparison ignores it. The next worker
  measuring real cannon-route audio should NOT raise the rate to "~96000"
  and treat that as "matching" — the tool says nothing about rate at all;
  residue is a sample-by-sample fact.
- Format cite table for the close-NEGATIVE fact is in
  `docs/handbook/audio.md` ("The canonical mgba format") and in the tool's
  `--help` text. The citations are `tools/mgba_capture.c:30-48` (header
  doc) and `tools/mgba_capture.c:947-967` (write logic); both verified on
  disk this session.
