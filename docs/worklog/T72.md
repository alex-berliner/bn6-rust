## Step 2 -- the cited predicate, setter, and rank loop -- MEASUREMENT

The reader the ticket names at asm/asm00_2.s:1894-1897:

```
1894    bl object_getFlag         ; reads CollisionDataPtr+0x3c (object.s:21627-21631)
1895    mov r1, #1
1896    lsl r1, r1, #0xf          ; r1 = 1<<15 = 0x8000
1897    tst r0, r1                ; flags1 & 0x8000 (CONFUSED) ?
```

Sits inside `playerObject_checkDirectionButtons_800FA54` (the
direction-buttons reader, asm00_2.s:1867-1907): when the bit is set, the
picked direction index is reloaded through `byte_800FAA4`
(asm00_2.s:1908-1910: `ldrb r6, [r2,r6]`) -- the 8-entry table holds
`00 02 01 04 03 00 00 00`, mapping each direction to a (possibly
inverted) replacement; this is the per-frame CONFUSED-divert predicate.
Bit index: **bit 15** of `oCollisionData_ObjectFlags1` (CollisionData.inc
offset 0x3c), CollisionData.inc:18 = OBJECT_FLAGS_CONFUSED enum = 0x8000.

The setter at asm/object.s:5483 (read out of the `docs/inventory/statuses.json`
canonical mapping):

```
5479    ldr r0, dword_800E984 // =0x30088
5480    bl object_clearFlag2                ; clear flags2 0x10008
5483    mov r0, #0
5484    strh r0, [r6,#oCollisionData_Unk_1c]    ; zero timer-ish
5486    strh r0, [r6,#oCollisionData_Unk_2a]
5488    strh r0, [r6,#oCollisionData_Unk_2c]
5490    ldr r0, dword_800E980 // =0x8000
5492    bl object_setFlag1                   ; SET flags1 bit 15 = CONFUSED
5494    ldr r0, dword_800E988 // =0x80010800  ; = INVIS|0x80000000
5496    bl object_clearFlag                  ; clear flags1 INVIS + high bit
5499    mov r7, #0x48
5501    add r7, r7, r6
5502    ldr r0, [r7]
5503    tst r0, r0
5504    bne loc_800E8E2
5505    mov r4, #0
5506    bl sub_80E09EE                       ; spawn the *ConfusedStar object
...    (countdown -- Timer at +0x22 decrements per frame, until <=0:
         clear IMMOBILIZED 0x4000 + clear CONFUSED 0x8000)
```

That is the rank-loop boundary the ticket asks for: the routine that
**applies** the bit (object_setFlag1 at object.s:5492) is itself the
per-frame **tick** -- after the SET it arms a count at
`oCollisionData_Unk_22` (+0x22 / 0x22 = BLIND_OR_CONFUSED timer byte,
the same shape as BLIND's BlindTimer at CollisionData.inc:134 +0x20) and
runs `sub r0,#1; strh` per frame; on underflow it clears both
IMMOBILIZED (0x4000) and CONFUSED (0x8000). The bit-flip site the next
ticket ports is therefore **a single byte write to bit 15 of
CollisionDataPtr+0x3c on the rank-loop boundary** (the same path T64
uses for BLIND, but inverting the bit -- this routine SETS 0x8000,
canon's tick then CLEARS it after the countdown).

The 0x8000 setter also appears at asm/asm00_2.s:1622 inside `sub_800F884`
(asm00_2.s:1613-1625: `ldr r0, dword_800F954 // =0x8000; bl object_setFlag2`),
but that writes flags2 (the inventory flags it as
OBJECT_FLAGS_2_UNK_BIT_15 -- different field, same numeric mask, not
CONFUSED). It is NOT the CONFUSED setter and is NOT relevant here.

Where the rank loop lives in `src/battle.rs`: T64's
cross-alliance BLIND gate at src/battle.rs:5193-5224 (the
`actor::opposing_player_blind()` read + per-enemy `Actor::show(frame, dy,
opposing_flags)` apply); the analogue for CONFUSED is mirroring the
same gate but reading an `actor::opposing_player_confused()` flag and
applying it as the **direction-invert trigger**, not the render
suppress (CONFUSED does NOT hide the object; it flips the direction
table). The mirror site is src/battle.rs:~5193 in the same
`for enemy in self.enemies.iter().filter(...)` block.

   (+0x22, decremented at object.s:5510-5518 and used as the
   "BLIND_OR_CONFUSED timer" -- the BLIND setter also writes here at

   ticket should confirm the byte is the SAME field for both BLIND and
   CONFUSED by reading T18's bit-census (statuses.json has both rows
   with the same offset via the `_counts`/`_loose` keys).
2. The `sub_80E09EE` spawn (object.s:5506) writes a new spawned effect
   object (the "ConfusedStar" / "?Ring" sprite). Whether the game's
   scene the chip hits ever renders it is the next measurement; the
   harness row is only a 0/0 with non-blind negative if CONFUSED
   doesn't fire on battle_full, which it does NOT (chip never sets it).

   `00 02 01 04 03 00 00 00` -- the port reads it as a constant
   `[u8; 8]` with the // canon: comment block, not as code-derived
   arithmetic (the proof of inversion is the table itself).
