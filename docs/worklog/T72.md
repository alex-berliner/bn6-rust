# T72 — the second status bit end to end: CONFUSED (flags1 0x8000)

Branch `wt/t72` on main d3cfa2c (wt/t64 and wt/t69 NOT merged, per the
coordinator's dependency note; the blind row was rebuilt from main's own
harness support). Verdict up front: **steps 1-3 measured in full; step 4
ported; step 5's row is RED at the confusion star ring — the ticket's
predicted 0/0/90 is refuted by measurement, and the refutation is precise**
(§2/§3). The numbers: enemy poke 11,436 px / worst 132 / first divergence
k=1; player poke 7,457 / 126 / k=1; both are the star ring ONLY, no
behavior divergence anywhere in the window.

## Step 3 — mechanism

- Reader `asm/asm00_2.s:1894-1897` (routine :1867-1902): direction-remap
  arm, inverts both axes (table above). Callers: `asm31.s:108100, 108724,
  109885, 110696, 110929, 113228, 119169` (naviMove states, chip-use).
- Enemy-AI arm on this route's object: the Mettaur RowCheck gate
  `flags1 & 0xa000` → Wander (`asm31.s:171391-171397`) — DORMANT in the
  window: the route's Mettaur decides only between attack cycles (canon
  attack anims start at captures 32 and 138; the window is 40..129), so
  neither the wander roll nor the direction arm can move a pixel. **This is
  the precise reason the reader's arm is pixel-invisible on this route.**
- Timer tick `sub_800E730`'s CONFUSED block, `asm/object.s:5457-5492`:
  decrement Unk_1e (:5458-5460), signed `bgt` (:5461) still-positive →
  re-assert 0x8000 (:5482-5483) and spawn the status effect object once per
  application (Unk_48 latch :5487-5492 → `sub_80E09EE` →
  `object_spawnType4(6)`, `asm31.s:85839-85855`) — the star ring; expiry →
  clear 0x8000 + flag2 0x80 + zero timer/latch (:5462-5468). The bit is
  DERIVED from timer > 0 each frame.
- Timer writer + initial length: `sub_8013EE6` (`asm00_2.s:11371-11378`)
  writes **0x12c = 300** to Unk_1e; the constant is `off_80141BC`, SHARED
  with blind/invuln helpers (T18 correction 6 — not confusion-specific).
  Chip path: StatusEffectFinal 0x2X → family 2 via `sub_801A554`
  (`asm00_2.s:22211`), durations 480/720/960/4/300/600 (dat01.s:155).
- Classification: the ring covers 90/90 frames of the window from k=1 (0 at
  k=0 — the poke boundary frame, T69's k=0 shape).

## Step 5 — the row is RED, and the ticket's prediction is refuted

The row reads the star-ring total, NOT 0/0/90: canon's tick spawns the ring
(step 2/3), this build has no type-4 effect objects to draw it, and the
draw machinery is outside this ticket's file list (sprite/effect-object
code), so porting it here would be scope widening. Measured refutation,
not a port defect: the SAME poke recipe measured canon-vs-canon is 11,436
px (§2) — that is the floor any port without the ring lands at. The
negative is non-blind (the ring moves with the frame shift).

## Ideas tried and dropped

- Parallel captures to save wall time: BROKEN (second capture came back a
  blank menu — content garbage). Run captures strictly sequentially.
- A flag-only poke (no timer) to isolate the reader arm: dead — the tick
  clears the bit the same frame (0-1 → signed -1 → expiry path), the row
  would read 0 everywhere and the negative would be BLIND.
- Porting the ring inside this ticket: rejected — new effect-object kind +
  sprite work outside the allowed files, no captures left in budget.
