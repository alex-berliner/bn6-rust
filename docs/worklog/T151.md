## Step 2 — the rank byte, read and cited (measurement)

- Identity table: `GetVerActorTyAndAIIdx_80182B4` (asm00_2.s:20021-20027) returns
  `&VerActorTyAIIdxTable_80182C4[3*enemy_idx]` (3-byte rows: Version, ActorType, AIIndex;
  table at asm00_2.s:20039-20044). Mettaur = ai_index 1, enemy_idxs 1..6 = versions 0..5;
  row 1 = `00 00 01` (rank 0), **row 2 = `01 00 01` (rank 1)** — the task's "row 1" wording
  was the stale variant; the rank-1 identity is row idx 2.
- The rank byte the spawner reads is the **EnemySetup quad's enemy-id byte**:
  `spawnEnemy_80073E2` (asm00_1.s:8724-8741) builds enemy_idx from quad[2]+quad[3] low
  nibble; the only version modifier on the route is `sub_800EC80` (asm/object.s:6066-6107):
  for ACTOR_TYPE_VIRUS rows it returns enemy_idx + min(2·X, 5−version) with
  X = max(sub_8000E30, sub_8014150); `sub_8000E30` (asm00_0.s:1524) is a literal `return 0`,
  `sub_8014150` (asm00_2.s:11729-11748) returns 2/1/0 from the PET's NaviCust
  virus-rank-up stats bytes 0x38/0x37. On a fresh save X = 0 → bump dormant → **the record's
  own id byte fields its exact rank** (T58/T87's live NameID reads all agree).
- Consequence: the bump is EVEN-only (2·X, clamped), so from v0 records the wild roll can
  never field v1/v3 (only v0/v2/v4/v5) — rank 1 needs a base record naming id 0x02. Census
  (ROM walk, this ticket): CentralArea1 (0x080b4b78) names NO v1/v2/v3 (T58's NEGATIVE
  confirmed); T87's EVENT_681 root (0x080b50b0, 12 records, all rec7=0) names Mettaur v0
  slots only (rec0/rec5/rec10/rec11). **Family A has them**: battleSettingsList0
  (0x080aee70) rec226 0x080afc90 (rec7=0, formation 0x080b0ab2: MegaMan (2,2) + 3× id 0x02
  at (4,1)/(5,3)/(6,2)), rec63 (v0+v1+v1), rec66 (v0+v1+v2), rec226-229 (v1 triplets);
  rec60 0x080af230 is rec226's rank-0 twin (ids 0x01 at (5,1)/(5,3)/(6,2)).
