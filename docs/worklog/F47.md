## Verdict (acceptance ladder)

(a) SCROLL PHASE at register level: NOT PROVABLE on this tooling (registers unreadable —
proven latch, quote above) and NOT the carrier anyway (<=2 px, zeroed exactly on 20/34).
(b) TRANSFER-LATENCY signature: PROVEN AS A SIGNATURE, mechanism-corrected — N=3, canon edges
captures 140,148,156,164,172 / rust edges 129,137,145,153 (dirs above), residual exactly in
the gap; the 3 frames live in the art-clock SEED, not the upload (our upload is same-frame by
construction). The ticket's (b) wording "our upload landing N frames late" is therefore only
evidence-true, not mechanism-true; the mechanism claim (clock phase) rests on
src/backdrop.rs:255-266 + battle.rs:2385-2403 being the whole story, which is code-read, not
measured.
(c) ART CONTENT: not settled (asset layout assumption failed; see Step 4).
(d) NEGATIVE: refuted — the sides do not match in the gap frames and the pairing is fine.
So: (b)-shaped with the clock-phase correction; smallest next dump to finish it: one pair at
the FIRST edge (canon count ~141 / rust count ~125, both sides' tile watch) plus a read of
BattleBackdropGFXAnimScript_807FB98's upload schedule to get the asset's true per-step tile
list — that separates "our timer seed is 3 frames late" from "canon's edge is 3 frames early
relative to a shared schedule", i.e. whose phase is canonical.
