## The canonical cite chain

`isBannerBusy_801E754` (reference/bn6f/asm/asm00_2.s:31105-31131):
- `ldr r2, off_801E77C // =eStruct2035280`
- `ldr r1, [r2,#oStruct2035280_HudElementMask]`
- `mov r0, #1; lsl r0, r0, #0xf; and r0, r1`
- `beq locret_801E778` -- mask bit 15 clear -> r0 == 0 (IDLE) -> advance
- otherwise: record busy (r0 == 1) or record idle but bit set (r0 == 2) -> stay

The BANNER_WAIT handler `bannerSeqState04BannerWait_8008064`
(reference/bn6f/asm/asm00_1.s:10568-10571) advances on r0 == 0:
```
loc_80080B2:
    bl isBannerBusy_801E754
    cmp r0, #0
    bne locret_80080D0     ; r0 != 0 -> return
    ...
    mov r0, #8
    str r0, [r5]           ; r0 == 0 -> SEQ_08
```

T7x measured the bit-15 series: 0xC497 k=175..232 (58 exports, exactly the
banner record's 58-update lifetime). Bit 15 SETS the moment the record spawns
(state-0 sub_801E792, asm00_2.s:31115-31220, calls
`setBattleHudElements_801BECC(1 << 15)`), CLEARS 58 updates later
(state-3 handler sub_801CEFA, asm00_2.s:27770-27779, calls
`clearBattleHudElements_801BED6(1 << 15)`).

## The port that meets the cited acceptance

The canonical port:
```rust
fn is_banner_idle(banner: Option<&Banner>, banner_was_up: bool) -> bool {
    banner.is_none() && banner_was_up
}
```
with `banner_was_up` latched at every visual-banner spawn site
(BATTLE_START via `banner_at` countdown, ENEMY/MEGAMAN DELETED at the
over-arm, fixture-forced banner), and the SEQ_04 leave edge:
```rust
SEQ_04 if is_banner_idle(self.banner.as_ref(), self.banner_was_up) => {
    self.seq.transition(SEQ_08)
}
```

The cursor regression is the canary the ticket explicitly forbids
("Cursor 1/1/170 must not move"). The mechanism:

- Our port's banner is spawned by the `banner_at = BATTLE_START_AFTER_WINDOW
  = 30` countdown, armed at the chip window close (src/battle.rs:3090)
  and ticked at src/battle.rs:3643-3647.
- At SEQ_04 entry, banner_at = 28 (2 frames were spent in SEQ_00). The
  banner spawns at SEQ_04 age 28, runs for 58 updates, dies at age ~85.
- `is_banner_idle` returns true at age 85; the fitted edge fired at
  age 59 (`SEQ04_FRAMES - 1 = 59`).
- The 26-frame delay holds the player in the gated state 26 frames longer
  than the fitted version. Cursor's tear is timing-sensitive; the delay
  shows up as 12 differing pixels on 12 additional frames.

## Why the canonical port cannot be done alone

Two distinct mechanisms are required to make `is_banner_idle` match the
fitted behavior:

1. **Spawn the banner at SEQ_04 entry, not 30 frames after window close.**
   Canon's record spawns at BANNER_WAIT's first run
   (`sub_801E792` is called immediately when the handler's byte-[r5,#3]
   == 0 branch fires, asm00_1.s:10520-10533). Our port delays the spawn
   30 frames so the BATTLE_START strip appears in the same screen
   position canon's windowclose-time record does; that delay is what
   gives the 26-frame `SEQ_04→SEQ_08` gap.
2. **Make the visual strip invisible during the windowclose scenario's
   compared window.** T7x's negative verdict (docs/worklog/T7x.md) shows
   the record's mere existence during windowclose's frames 81..120
   breaks pixels, even when the strip is not drawn
   (`Banner::hidden()` and objectless `Vec::new()` both regress with
   windowclose 63962/3557, byte-identical to each other). The
   mechanism was not pinned within T7x's budget.

T152b's fitted-edge replacement is therefore NOT a single-site edit; it
requires either re-tuning the banner_at timing (which is its own
fitted constant) or solving T7x's windowclose-strip mystery first.
