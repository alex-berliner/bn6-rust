## The canonical predicate (the cite the ticket named)

`stepBannerSequencer_800801C` (reference/bn6f/asm/asm00_1.s:10452-10518, dispatch
table at off_8008038 / `BannerSequencerStates_8008038`) is a 72-byte routine that
loads `eBattleSequencerState_203CA70`'s low byte, indexes the dispatch table, calls
the per-state handler, then reads [r5+4] (the entry byte) and returns.

The handler table (asm00_1.s:10488-10515) has 10 entries; the BANNER_WAIT handler
(`bannerSeqState04BannerWait_8008064`, asm00_1.s:10520-10586) is where the
banner-idle predicate lives:

```
10568  loc_80080B2:
10569      bl isBannerBusy_801E754
10570      cmp r0, #0
10571      bne locret_80080D0     // if NON-zero (busy), return
10572      mov r0, #0xff
10573      mov r1, #0
10574      bl sub_801E724
10575      mov r0, #0xff
10576      lsl r0, r0, #8
10577      add r0, #0xff
10578      bl sub_801E0C8
10579      // ... (banner-sub effect calls)
10582      mov r0, #8
10583      str r0, [r5]           // transition SEQ_04 -> SEQ_08
10584  locret_80080D0:
10585      pop {pc}
```

`isBannerBusy_801E754` (asm00_2.s:31105-31131): returns 0 when `eStruct2035280`
HUD mask bit 15 (0x020352C0 & 0x8000) is NOT set (mask byte 0x020352C0 reads
0x4497 live / 0x0084 past teardown; only the live mask has bit 15). Returns 1
when the mask bit IS set but the banner state at byte_2036848 is not 2 or 4 OR
the byte_2036840 != 4 (still busy). Returns 2 when the mask bit IS set AND
byte_2036848 in {2,4} AND byte_2036840 == 4 (banner record in idle state).

The `cmp r0, #0 / bne` in the BANNER_WAIT handler treats r0 == 0 (mask bit clear)
as "banner done, advance". r0 == 1 or 2 stays in BANNER_WAIT. The byte_2036840/8
fields are the banner RECORD state machine, separate from the visual banner
(`self.banner` in our model) — the record is spawned by `spawnBannerRecord_801E792`
at BANNER_WAIT entry and reaches byte_2036840 == 4 after 60 updates; canon's own
battle_full trace (k=136..195) carries this 60-frame wait on every route that
reaches the state, which is what the fitted SEQ04_FRAMES = 60 captures.

## What the port has to do

Replace the `SEQ04_FRAMES - 1` age threshold with the canonical predicate. Our
model approximates `isBannerBusy_801E754 == 0` as:

```rust
fn is_banner_idle(&self) -> bool {
    !self.hud_live || (self.banner.is_none() && self.banner_was_up)
}
```

`!self.hud_live` is the mask-bit-clear arm (HUD teardown happened — no banner
in flight). `self.banner.is_none() && self.banner_was_up` is the banner-record-
idle arm: the visual banner was up and is now gone. The `banner_was_up` latch
is what models the record's 60-update lifetime (canon's record is spawned at
BANNER_WAIT entry and dies 60 updates later; our visual banner is up for
SCALE.len() = 58 frames, and we latch "was up" the moment the visual appears
so the clear-and-stay-clear path returns idle).

For the battlestart_scripted scenario, the sequencer never leaves SEQ_00
(`entry_park` pins the age, no window opens, no banner is ever spawned), so
the predicate is never consulted. For windowclose_full, the compared window
is canon frames 81..120 — the SEQ_04 -> SEQ_08 transition (canon ~frame 143)
is OUTSIDE this window, so the timing change does not regress pixels.
