## Design (settled before editing)

1. `src/emotion.rs`: delete the static `emotion == 5 || emotion == 6` no-sprite
   arm; slots 5/6 build sprites from FACE_INDEX[5]/[6] like every other slot
   (T123 verified the slot-5 render is pixel-exact). The `Emotion` struct gains
   the modeled eStruct bytes: `blink_countdown` (+0xf) and `blink_cycles`
   (+0x1d). `show` gates on countdown 5/6 (the transcribed drawer test);
   `update` ports sub_801CC94's ACTIVE arm (decrement, wrap-reload 0xc). The
   ARMING path (timer +0x38, r5[0x15]/0x17/0x1e conditions,
   GetPositiveSignedRNGSecondary) is NOT ported — porting it would consume RNG
   and needs sub_80103EC/sub_800FE52; on every compared route canon's countdown
   is flat 0x00 (T123 100-frame watch), so the cycle counter stays 0 and the
   active arm never fires yet. Nothing fitted: the period 0xc is transcribed
   from :27655-27656/:27674-27675.
2. Countdown input: the descriptor is FULL (64 bytes, every offset spoken
   for). Extend FIXTURE_SIZE 64 -> 66 with a new byte +64 `blink_countdown`
   ("NOT IN FIXTURE.md" precedent, same as +63 emotion): the initial value of
   the ported countdown byte, 0 = the never-armed default every existing row
   already behaves as. mgba_capture takes 64 cheats; 33 is fine.
   emotion_skip's and form_cross's rust descriptors get blink_countdown=5,
   mirroring canon's at-load poke 0x0203528e:0x0500 (nothing writes the byte
   on either side afterwards — measured on canon by T105/T122, and the port's
   active arm never fires).
3. Negative fixture: the harness's negative kinds (frame/pixel shift) cannot
   zero the ported write. `Check` gains `negative_rust` — an alternative rust
   Side run as a THIRD capture at the row's own align; emotion_skip's is the
   same descriptor with blink_countdown=0. Zeroing the ported write must make
   the row read the face (T123's measured 694/frame profile).
