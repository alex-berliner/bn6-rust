## Step 2 — canon cites (all assembled from the disassembly + T151a finding)

- **VerActorTyAIIdxTable_80182C4** row 2 = `01 00 01` (version 1, ACTOR_TYPE_VIRUS,
  ai_index 1 = Mettaur) -- asm00_2.s:20046, table at asm00_2.s:20039-20044. Reader
  GetVerActorTyAndAIIdx_80182B4 asm00_2.s:20021-20027 = `&table[3*enemy_idx]`.
- **sub_800EC80** (asm/object.s:6066-6107) -- the ONLY version modifier on the route.
  For ACTOR_TYPE_VIRUS rows returns enemy_idx + min(2·X, 5-version) where
  X = max(sub_8000E30 asm00_0.s:1524 = literal 0,
  sub_8014150 asm00_2.s:11729 = PET NaviCust virus-rank-up bytes 0x38/0x37). X=0 on a
  fresh save -> bump dormant -> **the record's own id byte fields its exact rank**.
- **spawnEnemy_80073E2** (asm00_1.s:8724-8741) -- the rank byte lives in the EnemySetup
  quad id: `quad[2] + (quad[3] & 0xf) * 0x100` = enemy_idx. **T151a finding**: rank byte
  lives in EnemySetup, NOT in the identity row directly.
- **T151a BLOCKED finding**: the rank1 mechanism is `sub_800EC80 quad id`, NOT
  `byte_80182C4 row 1`. Runtime ROM poke of the identity row is dead
  (--poke-at 60:0x080182C5:0x0001 left row bytes 00 00 01 and slots HP 0x0028; mgba
  busWrite16 cannot write ROM, T151 measured).
- **T87 lever**: selectEncounterTableForMap_80AA5F4 (asm/asm29.s:10344-10371) reads
  EVENT_67F/680/681 and swaps the encounter-table root. Under EVENT_681, (net group
  0x10, map 0) = list 0x080b50b0 (12 records, ALL rec7=0). iCurrFrame 0x37a -> roll
  reads 0x37b = 891, 891 mod 12 = 3 -> rec3 0x080b50e0 = byte_80B580A (formation with
  enemy ids 0x85 + 0x13 = Gunner + ai4 v0).
- **ROM-walk of T87 EVENT_681 list** 0x080b50b0 (data/dat30.s:3254-3283, 12 records
  byte_80B57C6..byte_80B5882): NO record has Mettaur rank-1 (id 0x02) quads. Records
  are v0 (0x01), Gunner (0x85), ai4 (0x13), and 0x1F/0x37 shells only. Hence the
  "T87 lever alone" cannot give Mettaur v1; the rank1 byte poke is required.
- **T131 OPT path** (asm/asm29.s:10216-10234): oS2001c04_Unk_28 u32 @0x02001c2c nonzero
  + GetPositiveSignedRNG bit0==0 + oS2001c04_OptCurBattleDataPtr (ptr>>0x18)==8 -> the
  roll ADOPTS the pre-chosen BattleSettings record wholesale, no root walk, no rec7
  gate, no count. This is the **rank1 byte poke per T151a**: the OPT lever re-aims
  CurBattleDataPtr (which is what the spawner reads via `oBattleSettings_EnemySetupArrPtr`)
  to rec226 0x080afc90 = formation 0x080b0ab2 = MegaMan (2,2) + 3x enemy_idx 2 = Mettaur

- **T131 seed admission halfwords** (0x7734d7c1 @0x020013f0/f2): the OPT draw needs
  bit0==0; the natural-chain seed rejects the OPT branch (T131 C1 measurement).

## Ideas tried and dropped

- "Poke the rank byte at the EnemySetup quad" (T151a's framing): impossible at runtime.
  oBattleSettings_EnemySetupArrPtr is a plain ROM pointer (asm00_1.s:8546-8557), the
  EnemySetup array stays in ROM, mgba busWrite16 cannot write ROM (T151 measured).
  Implemented instead as the BattleSettings-pointer route: T131's OPT lever re-aims
  CurBattleDataPtr to rec226, whose formation 0x080b0ab2 has 3x enemy_idx 2 quads. This
  is the SAME byte the spawner consumes (per T151a finding), via RAM pokes the game
  itself reads.
- "T87 lever alone gives Mettaur v1": false -- ROM-walked 0x080b50b0's 12 records
  (data/dat30.s:3254-3283) and none has id 0x02 quads. The T87 levers are kept in the
  recipe (they feed only the path the OPT adoption skips) but they don't drive the
  record pick on this route.
- Post-load poke of the adopted pointer 0x02001b9c: dead (both arms spawn baked-in
  rec163, T151 measured). The OPT adoption is consumed during the BUILD; the rank
  lever must be the recipe's frame-59 pokes.
