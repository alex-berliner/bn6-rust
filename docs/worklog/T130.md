## Step 1 — the writer pinned, with the guard polarity CORRECTED (the ticket had it backwards)

`object_panel_setPoison` (asm/object.s:2540-2563), instruction stream:

```
bl object_getPanelDataOffset      ; r0 = panel data ptr (or 0)
tst r0, r0 / beq -> return 0      ; no panel -> no poison
ldr r1, [r0,#0x14]                ; Flags
mov r2, #0x10
tst r1, r2                        ; Z = (Flags & 0x10 == 0)
beq -> return 0                   ; taken when the bit is CLEAR
ldr r2, =0x3f5f (dword_800CBD0) / bic r1, r2
ldr r2, =0x114  (off_800CBD4)   / orr r1, r2 / str r1, [r0,#0x14]
mov r2, #4 / strb [Type +0x2] / strb [Animation +0x6]
mov r0, #0x90 / bl PlaySoundEffect / return 1
```

**The guard's meaning: `tst`+`beq` branches to the return-0 tail when `Flags & 0x10` is
CLEAR, so a panel is poisoned only when bit 0x10 IS SET.** The ticket (and its restatement
of the verifier's reading — "only a panel whose Flags & 0x10 is zero is poisoned", "a panel
with the bit set is skipped") states the opposite polarity. Normal panels carry 0x10
(0x00010032/0x00010012), the table words for hole (0x18000) and broken (0x14000) do NOT —
so the guard's visible effect is: poison cannot land on a hole or a broken panel. The same
guard shape guards every writer of the crack/break family (object.s:2215-2563: `tst #0x10;
beq` at each of object_crackPanel/object_breakPanel/object_breakPanelLoud/dups).

Caller chain pinned: `byte_80E2588` (asm31.s:89651-89667) is 3 entries × 0x18 bytes
(Param1 0/1/2); entry +0x14 holds the writer pointer (`object_crackPanelDup1+1`,
`object_breakPanel_dup3+1`, `object_panel_setPoison+1` — the ONLY reference to setPoison in
the whole ROM: no `bl` site anywhere, grep-checked). `t4_0x1e_80E25D0` (asm31.s:89665-89681)
dispatches on CurState through `off_80E25E4` → {sub_80E25F0 (setup: ExtraVars =
entry base, then collector by entry+1 byte via off_80E2620), sub_80E2628 (per-frame drip:
Timer 8 → one panel per 8 frames off the shuffled list, writer at entry+0x14), sub_80E268C
(teardown)}.

**Two honest gaps, reported not papered over** (both next-ticket material):
1. The live flip is 9 panels in ONE frame; `sub_80E2628`'s drip is one panel per 8 frames.
   Nine one-panel objects spawned together (Timer=8 → all write the same frame) would fit,
   as would a writer path not through this object; unverified either way. What the capture
   *does* pin: the flip lands the frame after the pod's occupancy bit appears/clears
   (52→53), so the +8-drip read of the sheet route is not what happened live.
2. The poison entry's collector words (sub_80E269A passes [entry+4] as want-SET and
   [entry+8] as want-CLEAR to `object_checkPanelParameters`, object.s:2688-2713) decode to
   want_set=0, want_clear=0x10 for entry 2 — the collector would pre-filter OUT the very
   panels setPoison's guard requires. My byte alignment of the entries may be off by the
   tail word (the listing's 3 entries are 28+24+20 bytes against a 0x18 stride); the
   alignment of +4/+8 per entry is the part to re-derive before leaning on it.

Our corresponding object today: the PoisSeed sheet arm in `src/battle.rs`'s
`poison_pending` block (sheet loop over cols 4-6 × rows 1-3, one frame after the pod lands)
and the VDoll `rest_poisons` arm (single panel, object_setPanelType 4 at the landing,
sub_80D47C0 loc_80D481E) — plus `src/field.rs`'s `Panels`, which until this ticket had no
flag word at all.

## Step 2 — the two citation defects fixed (plus the area rule re-stated)

- `bn6f.map:34342` is `0x081d6000 IWRAMRoutinesROMLocation` (read the line) — not the
  table. `word_3007924` is in no map line (grep). Correct provenance, from the copy
  routine itself (reference/bn6f/asm/start.s, `start_copyMemory` call):
  `IWRAMRoutinesROMLocation -> 0x3005B00, size 0x1ed4`; the table's IWRAM address gives
  `0x3007924 - 0x3005B00 = 0x1e24`, so ROM `0x081d6000 + 0x1e24 = 0x081d7e24`, and
  `0x1e24 < 0x1ed4` is inside the copy. Fixed in `docs/coverage/panels.md` and
  `tools/panel_flags_export.py` (docstring + comment only).
- The "each entry gated by the 0x10 guard byte" aside is gone: the `0x10`s inside
  `byte_80E2588` are per-entry check words fed to `object_checkPanelParameters`
  (want-set/want-clear), while setPoison's guard is an immediate `#0x10` tested against the
  panel's own Flags. Two unrelated 0x10s. Also corrected: "per-CurState writer table" →
  CurState picks the routine (off_80E25E4), Param1 picks the entry (Param1*0x18).
- Area rule, from `sub_80E269A`'s own loop (asm31.s:89775-89810): the collector enumerates
  **cols 6..1 × rows 3..1 = all 18 panels** and keeps those passing
  `object_checkPanelParameters(col, row, [entry+4], [entry+8])`, then shuffles the survivors.
  The listing pins the enumeration and the filter, not the final shape; the LIVE shape is
  measured: nine panels, cols 4-6 × rows 1-3 (the enemy half, 3x3). "3x2" is refuted and no
  "3x2" claim remains anywhere.
