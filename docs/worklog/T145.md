## Canon-side route: measured, with a mechanism finding

1. **ROM pokes are a no-op**: `--poke 0x080b5351:0x0185` (the Gunner id
   halfword in record 6's setup array 0x080b5347) does not land — probe.py
   peek after frame 2 still reads 0x0085. mgba ignores bus writes to ROM.
2. **Spawn timing on the row capture**: from battlestart_gunner.state, slot 1
   populates at capture frame 69: NameID 0x0085, AIDataPtr 0x02034280 (watched
   at +0x58 = 0x0203abb8), AIData halfword 0x1700 (ActorType 0, AIIndex
   0x17 — T12's known-answer, now measured live), HP 0x003c, CurState 4.
3. **Fork latch finding (mechanism, corrects the recon's model)**: poke-at 70
   of AIData → 0x1701 (ActorType 1, AIIndex 0x17) + NameID → 0x0185 holds
   (watched through frame 110: values stable, HP 60, no crash) — but
   CurState_CurAction stays 0x0004 and NOTHING else changes. Both dispatchers
   (virusObject_dispatch_8108F50 asm31.s:169291-169301,
   naviObject_dispatch_80F2330 asm31.s:123304-123312) are UNBOUNDED
   CurState-indexed `bx` tables; CurState 4 through off_80F2348 would read
   the word at 0x080F2358 (mid-instruction bytes of sub_80F2354, 0x00847801
   shape — the verifier's predicted fault) and crash. No crash + no change
   means the ActorType byte is NOT re-read per frame: **the T1
   t1_0x0_80B81EC fork is latched at spawn**; a live ActorType flip changes
   only NameID-keyed struct reads, not the dispatch. This reframes T134's
   step-3 crash hunt: the flip itself is harmless; whatever crashed that
   session was the frozen-core artifact the T134 verifier already named.
4. **True-spawn routes closed**: (a) CurBattleDataPtr 0x02001b9c repoint to a
   fake record in free EWRAM (0x0203E000, verified zeros) with setup id 0x0185
   — the repoint sticks (watched), but the spawn still builds the Gunner, so
   spawn reads ids from a RAM copy made earlier in battle init, not through
   the record pointer; (b) patching battlestart_gunner.state's bytes — the
   RASTATE is PNG+compressed sections, the setup pattern (11 25 01 00 11 36
   85 00) is not in the raw file; (c) watch-write on NameID shows the spawn
   write comes from an init fill (0x08007762, lr 0x0800F243) — hunting the
   RAM setup array was cut off by budget.
5. **Chosen scenario**: flip route — poke-at 70: 0x02034280:0x1701,
   0x0203ab88:0x0185. Canon = Gunner-presenting object with navi identity
   (NameID 0x0185 → navi struct columns for every NameID-keyed read) whose
   per-frame brain is unchanged (latched). Our rust side therefore ports the
   fork as data + Kind wiring and runs the SAME per-frame think arm the
   dispatch actually services for AIIndex 0x17 (ForGunner_8113078), with the
   latch finding cited in code.
