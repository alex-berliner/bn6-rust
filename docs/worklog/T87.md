## Results (steps 1-2 traps, measured live)

- The roll is called by checkThenStartBattle_8005A8C (asm00_1.s:5272-5296) -- its gate
  chain is map-INDEPENDENT; the encounter-rate table byte_8020CE4[(g<<4)|m] (asm29.s
  10167-10171, 7 = never) reads 5 for both CentralArea1 (0x100) and the g16-m6 target
  (0x106), 3 for the g13-m4 first attempt.
- DEAD ROUTE 1 (GameState.MapId write): poking 0x02001b84 (any target map: 0x0690 for
  g16 m6, 0x8d/04-word pair for g13 m4) WEDGES the overworld: iCurrFrame freezes at
  poke+1 forever, rollRandomEncounter_80AA4C0 is never entered again (Unk_14 at
  0x02001c18 stays 0 -- the roll never ran, so it is NOT a threshold failure),
  SubsystemIndex sticks at 4, no battle. Reproduced twice with two lever values.
- DEAD ROUTE 2 (byte-width intent): --poke-at writes a u16; "0x02001b85:0x0006" also
  zeroed GameState.GameProgress (loc=0x6). Same wedge symptom; fixed by writing the
  MapId union word -- but route 1 still killed it, hence the flag flip.
- WORKING ROUTE: EVENT_681 (0x02001d58 bit 0x40, u16 0x0240 with the 0x02 neighbour
  preserved) swaps the internet group-table root (asm29.s:10362-10371, root 0x08020188);
  its (net g0x10, map 0) slot -- map 0 UNTOUCHED -- is list 0x080b50b0. The overworld
  keeps running (the swap is read only inside selectEncounterTableForMap).
- Lever class constraint: (V+1) mod 12 == 3 forces V = 0x36e (natural-4) or 0x37a
  (natural+8) near the natural ~0x372. 0x37a used; with the map write gone the counter
  keeps ticking and the roll lands on rec3 as predicted.
