## Step 3 — Implementation

Wrote `damage_element_mult(chip_element, def_elem, def_weakness) -> u32` as a
`#[inline]` (non-pub) function in `src/battle.rs` next to the bomb-element
constants. The PRIMARY 25-byte table is inlined as a `match (def, atk)` rather
than exposed as a `const [u8; 25]` to avoid the T146b regression path (cursor
1→10/9/170 from .rodata table exposure). The SECONDARY rule is a one-line
bitfield test.

CONSTANTS (every line tagged):
- The PRIMARY match: `derived` from ROM 0x081d7944 / asm38.s:3543-3555 (the
  match arms are direct cells of the 5×5 cycle HEAT→AQUA→ELEC→WOOD).
- The CHIP_ELEM→ELEM map: `derived` from constants/constants.inc:117-127.
- The `+1` for the four core elements (FIRE→HEAT=1 etc.): `derived` from the
  PRIMARY table's own diagonal cycle being only consistent with ELEM numbering
  0..4 (elements.md §6 derivation).

Wired into the sword strike (battle.rs:4796-4801) and AirShot strike
(battle.rs:4816-4822) call sites only:

```rust
let mult = damage_element_mult(chip.element, 0, 0); // def_elem=0, def_weak=0 fixtures
let dmg = (chip.power as u32 * mult).min(u16::MAX as u32) as u16;
enemy.take_damage(dmg);
```

NOT wired:
- Bomb paths (T146 BLOCKED step 5: Bomb.element regressed cursor 16000+ pixels;
  the ticket's RULES forbid re-opening it).
- Bus-ter, shockwave, enemy-on-MegaMan (no chip.element to read).
- The shot-damage path (cannon orb hits enemy at hop time) — Cannon has
  element=NONE=0x0A → mult=1, so `shot.damage = chip.power` is unchanged.

For every existing fixture pair, `chip.element == 0x0A` (Cannon) AND `def_elem=0`

the pre-port `enemy.take_damage(chip.power)`. Wiring is byte-inert.
