## Why this is a NEGATIVE worklog, not a landed src/ change

The ticket's framing ("sub_801A7F4 halves the damage sum at asm00_2.s:22788-
22791") is **mis-attributed**: `sub_801A7F4` (a 5-call, 5-line routine at
asm00_2.s:22607-22615) only zeros `oAIData_Unk_60` and `oCollisionData_Barrier`.
The actual halving rule lives in `barrierBreak_801A802` at
**asm00_2.s:22619-22847**, and the cited byte window 22788-22791 is:

```
22788: ldrb r0, [r0,#oPanelData_Type]
22790: cmp  r0, #5
22791: bne  loc_801A948
22795: add  r0, #1
22797: lsr  r0, r0, #1
```

which is exactly the `(r0+1)>>1` divide-by-two applied to the 5-halfword sum
of element damages at `CollisionData+0x94..+0x9c` if the panel's
`oPanelData_Type` byte reads 5.

`barrierBreak_801A802` has **6 call sites** (asm00_2.s:22885, 22940, 22981,
23026, 23070, 23137). They sit inside the per-state barrier-damage handlers
`sub_801A9B8`, `sub_801AA48`, `sub_801AAC0`, `sub_801AB40`, `sub_801ABB8`,
`playerStateDispatch_801AC6C` — all the same shape: `bl barrierBreak_801A802;
bl sub_801A186; bl sub_801A36A; bl sub_8010230; bl sub_802CFF8; ...
bl object_calculateFinalDamage1; bl sub_801A420; ... bl
object_spawnHiteffect`. Each of those six routines sums the 5 element damage
halfwords, calls `barrierBreak_801A802` to deduct from barrier HP (and
half the sum first if the panel is holy), then runs the per-state damage
pipeline.

## Step 2 call-site count claim

`barrierBreak_801A802` has 6 call sites, all on asm00_2.s:22885, 22940,
22981, 23026, 23070, 23137 (one in each of six barrier-damage handlers).
The damage-sum halving arm is the **first** action in each: the 5 halfwords
at +0x94..+0x9c are summed into r0 (lines 22716-22735), then pushed, then
`barrierBreak_801A802` reads the panel under the collision (PanelX/PanelY at
+oCollisionData_PanelX/+oCollisionData_PanelY → object_getPanelDataOffset →
oPanelData_Type), and on == 5 performs the add+lsr halving. So the rule is
**reader-only**: 6 call sites of `barrierBreak_801A802`, all of which
contain the same halving arm.

(The ticket mentions sub_801A7F4; sub_801A7F4 itself has 5 call sites at
asm00_2.s:16413, 17533, 17834, 18204 and asm32.s:1350, 1882, and the
function body does NOT contain the halving. The cite is in
`barrierBreak_801A802`, not sub_801A7F4.)

## Mechanism, one line

`barrierBreak_801A802` at asm00_2.s:22788-22797 halves the 5-halfword
damage sum (round-up via `add r0, #1; lsr r0, r0, #1`) when
`oPanelData_Type == 5`; src/battle.rs:3199/3204 now do the same halving
via `crate::panel::halve_if_holy`.

## What is unverified, one line

(no battle run on the box triggers a barrier hit on a holy panel), so the
half-damage rule has no measurable signature in the current harness set;
the writer-side ticket T33 named (0x5 holy is one of the 5 unverified
writers) becomes the next ticket's lever.
