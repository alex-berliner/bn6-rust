## Step 1 — decode the tables (measurement only, no build)

- ROM: `/tmp/bn6f_real.gba` 8388608 bytes, sha256
  `a37c1028adb72082b51e142321fa437967bc54b6f46730a53f6581ad455ad670`.
- Primary table `byte_3007444`: routine reads `defender*5 + attacker`
  (asm38.s:3534-3536); 25 bytes found at ROM 0x081d7944 (unique match), rows
  quoted in docs/coverage/elements.md §2. One extra hit per weakness,
  additive (`mul r0,r4` over `1+primary+secondary+bubble+elecBubble`,
  asm38.s:3483-3520).
- Secondary: no table — a bitfield rule (asm38.s:3634-3692), §3 of
  elements.md. The 0x80 special case keys on the attacker's
  `SelfCollisionTypeFlags & 0x2000`; that flag has no name in the .inc.
- Defender bytes: Struct2's first halfword is **element<<12 | hp&0xfff**
  (asm00_1.s:9240-9249 masks 12 bits for HP, shifts 12 for Element) — the
  `elem_hp` question is settled: element AND HP ride together. Struct1's
  Element (+5) ORs into BattleObject.Element (asm00_2.s:17637), its
  SecondaryElementWeakness (+6) goes to collision+0x18 (asm00_2.s:21358).
- Walked all 32 entries of both tables: **Mettaur (ai 0x01) and Gunner
  (ai 0x17) both read element 0, weakness 0**; only ai 0x19 (cursor w=0x40)
  and ai 0x1a (wind w=0x20) have nonzero weakness; 13 viruses have nonzero
  element nibbles (list in elements.md §5). `off_8109150[4]` row 0
  (0x0810ae4c) = 0x005a → HP 90, element 0.
- Attacker element: `BattleObject.Element` splits into collision
  PrimaryElement (low nibble) / SecondaryElement (high nibble)
  (asm00_2.s:21347-21351). Chip records carry `ChipElement` at +0x6.
  CHIP_ELEM→ELEM mapping (+1 for fire/aqua/elec/wood, flag bits for
  sword/cursor/wind/break) is **derived from the table structure + enums,
  not yet from a found conversion site** — I searched for an 11-byte
  CHIP_ELEM→element-byte table in the ROM (pattern `01 02 03 04 ...` with
  0x80/0x40/0x20/0x10 in the sword/cursor/wind/break positions) and found
  none; canon most likely converts per-chip in the chip scripts. The
  multiplier tables themselves are measured; the mapping is the one weak
  link and is named as such.

Ideas tried and dropped:
- Looking for the CHIP_ELEM→element-byte conversion table in ROM: not found
  (5 candidate hits, none matched the secondary bit positions). Next worker:

- Reading the IWRAM table bytes from the live game: unnecessary — the
