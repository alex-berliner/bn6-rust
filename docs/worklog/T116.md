# T116 — name the chip set a battle can actually reach, measured from the ROM

Branch `wt/T116` from main 53a3c54.

## Step 1 — canon's own reader of ChipDataArr_8021DA8 (measurement)

- `getChip8021DA8` (`reference/bn6f/asm/asm02.s:2-14`): `r0 = ChipDataArr_8021DA8 + id*44`
  (stride 0x2c = 44, `mul r0, r2` with `mov r2, #44`).
- Called at **chip use**: `useChipFromHand_800FB54` (`asm/asm00_2.s:2037`, `:2107`),
  and at battle init by the folder anti-cheat `tooManyGigasMegasAntiCheatHappensHere_800B022`
  (`asm/asm00_1.s:17483`, `:17556`), whose own id cap is the table length:
  `dword_800B104 = 0x19b` (`asm/asm00_1.s:17513`; items with id >= 0x19b become the error chip).
- Called at the **custom-screen/chip-select draw**: `sub_8027D10` (`asm/asm03_0.s:3780-8832`,
  10 call sites); the card renderer's 0x540 copy is at `asm03_0.s:4399-4409` with the
  `getChip8021DA8` call at `:4427` (matches the layout cite in tools/chip_export.py's header).
- Live verification (`mgba_capture --dump 0x8021DD4:0x2c`, `--dump 0x8022B94:0x2c` on
  `/tmp/bn6f_real.gba`, 30 frames):
  - id 1 Cannon @0x8021DD4: codes `1a020100`, elem 00, libtype 0, mb 6, fam 14, pw 40 — byte-identical to `data/ChipDataArr.s` block 1.
  - id 81 StepSwrd @0x8022B94: codes `ff0f0b01`, elem 00, libtype 0, mb 28, fam 13, sub 01, pw 160 — byte-identical to block 81.
  - Trap for the next reader: my first --dump of id 81 used 0x8022B6C (I computed 81*44 as
    0xDCC; it is 0xDEC) and read the tail of id 80's record. The ROM/base/stride were never in doubt.

## Step 2 — the reachable set R (measurement)

Gates, each cited (full derivation in `docs/coverage/chips.md`):
1. id < 0x19B = 411 (`tooManyGigasMegasAntiCheatHappensHere_800B022`, `asm/asm00_1.s:17513`).
2. record has ≥1 code: a folder item is an (id, code) pair; the pack quantity lookup matches
   the code against the record's four code bytes (`getOffsetToQuantityOfChipCodeMaybe_8021c7c`,
   `asm/asm03_0.s:305-333`). Exactly one named id has no code: MegaBstr (id 0).
3. a display name: `TextScriptChipNames0.s` has 238 strings indexed by chip id (ids 0..237).

**R = 237: ids 1..237** (232 named ids minus id 0's no-code gate; classes: standard 223,
mega 40, giga 13, secret 28).

Battery-save cross-check (`/tmp/bn6f_real.srm`, read only, never tracked): the save is a
minimal demo save; its EWRAM pack dumped live (`--loadsave` + 400 frames, then
`--dump 0x2002230:0x1400` — `getOffsetToQuantityOfChipCodeMaybe_8021c7c`'s 12-bytes-per-id
region) owns 12 chip types (1, 4, 5, 54, 71, 72, 89, 154, 163, 175, 184, 192), all inside R.
Ideas dropped: a naive srm scan for a 411-bit owned bitmap (candidate at 0x191c has bits set
beyond id 237, decode ambiguous — abandoned for the EWRAM dump, which is decisive);
deriving reachability from `IDSortPos`/`TextScriptChipNames1` (asm32.s:35412's table pick
reads a 0x20-stride UI record, not the 0x2c chip record — unverified mechanism, dropped).
