**Reading the field**. `enemy_state_action` is the u16 at `0x0203ab68 = 0x0203ab60 + 8`
(slot 2 BattleObject, `oBattleObject_CurState_CurAction`, BattleObject.inc:44). It's
`CurState | CurAction << 8`, so:
- canon `(4, 10)` at k=0: CurState=4 = `CUR_STATE_UPDATE` (alive/updating), CurAction=10 = `0x0A`
- rust `(4, 0)` at k=0:  CurState=4 = `CUR_STATE_UPDATE` (alive/updating), CurAction=0  = `0x00`

Both sides agree on CurState=4 (the object is alive and updating through the comparison
window); the divergence is the high byte, CurAction.

**Cite the routine**. `0x0A` is the Mettaur's *hop executor* CurAction (per `src/actor.rs:651`,
"ForMettaur_8109EF4 entry (asm31.s:170982) ... 0x0a hop executor"). The Mettaur's per-type
entry is `ForMettaur_8109EF4` at `reference/bn6f/asm/asm31.s:170982`, reached through
`virusObject_dispatch_8108F50` (`reference/bn6f/asm/asm31.s:169297`) and the CurAction
handler table at `reference/bn6f/asm/asm31.s:171011`. The 0x0A arm is the hop executor
`sub_8109CE6` (`reference/bn6f/asm/asm31.s:170689`).

**Rust side at k=0**. The actor's `oracle_fields` (`src/actor.rs:674-707`) maps the rust
`Action` enum to a CurAction byte:
- `Action::Hidden | Action::Appearing { .. } => 0x00` (the spawn-animation state, line 696)

So the rust side returns 0x00 at k=0 because the Mettaur is in `Action::Hidden` (initial
spawn frame), but the canon side is already in CurAction=0x0A (the hop executor idle).
Both sides agree on CurState=4; the divergence is the CurAction byte. The fix on the rust
side would be to leave the enemy's initial `Action` in the idle/hop path (so `oracle_fields`
exports 0x0A at battle frame 0), but that's a Rust change, not a tools change -- **out of
scope for this recon ticket**.

(Pattern note: 475/540 frames differ on `enemy_state_action`. The divergence is sustained
across the whole battle, not just at k=0; the same `Action::Hidden → 0x00` mapping fires
whenever the rust enemy is in `Hidden`/`Appearing` while canon is in some other CurAction.
The first-divergence frame is the FIRST frame where this disagreement appears, which is
k=0 -- battle frame 0, the very first compared frame.)

### Step 3a — diffmask.py fix (commit `d5ab8b2`)

The `--frames` smoke test surfaced a regression: T47's `e8ce477` refactored the diff
logic into a module-level `diff_one()` function but left `from PIL import Image`
imported only inside `main()`'s local scope (`tools/diffmask.py:99`). `diff_one` uses
`Image.new` at `tools/diffmask.py:64`, so calling it from `main()` raised
`NameError: name 'Image' is not defined` on every code path (single-frame and
`--frames`). T47's smoke test never caught it because the test directories were empty
(`/tmp/pf_{canon,rust}/` are T44's stubs), so the call short-circuited with
`'--frames: empty directory'` before reaching it.

The fix is one line: add the local import at the top of `diff_one()`. Verified by
re-running both paths -- the single-frame path now reports
`27819/38400 differing (72.45%)` and the `--frames` path reports
`367930/1190400 differing (30.91%)`. See commit `d5ab8b2`.

   `enemy_state_action` mismatch (475/540 frames) on the battle_full scenario. The
   next routine to port is `sub_8109CE6` (`reference/bn6f/asm/asm31.s:170689`).
2. **mm_state_action / mm_anim / mm_timer** (first divergence at k=250 / 251 / 269):
   close to T7r's residual 76/78/270; T7r's scripted A@170 arc is the same arc as
   battle_full's chip-window-open path. The next step would be to port the chip-execute
   chain (the CurAction-4 handler `sub_80C5D84` at `reference/bn6f/asm/asm31.s:29664`,
   cited at `src/battle.rs:1461`).
3. **rng_cadence** (first divergence at k=124, same frame T7r's chip-window opens):
   canon's gauge-pause `chimes` (`reference/bn6f/asm/asm00_1.s:15203-15218`,
