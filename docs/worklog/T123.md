# T123 — emotion 5/6: the blink countdown vs the cross-state face

Branch `wt/t123`, worktree `/tmp/bnwt/t123`, base 3ad4c4b. Ticket: canon's 5/6
is a 12-frame blink countdown at eStruct2035280+0xf, not a face-slot gate; the
port's `src/emotion.rs` builds no sprites for slots 5/6, so a cross-state face
is missing. `tools/harness.py` and `tools/states.py` may be touched; NOT
src/battle.rs, src/main.rs, vendor/.

## VERDICT (read this first): bounded NEGATIVE + one measured surprise

The port defect is REAL and the fix WORKS — but the ticket's acceptance row is
impossible on this route and the fix breaks a frozen row. Both blocks are
measured, not guessed:

1. The cross state IS reachable through the transformation byte (below), but
   canon's cross state repaints MegaMan himself: 587 px/frame of non-face
   delta that the descriptor route cannot reproduce. Even with the port fixed
   and the face matching pixel-exactly, the row bottoms out at 587/frame —
   a box, which this project does not land. The 0/0/40 cross row needs a
   battle-side cross model = src/battle.rs, which the ticket forbids.
2. ANY fix that draws slots 5/6 breaks the frozen `emotion_skip` row: its rust
   side is descriptor emotion=5 (draws the face after the fix) against canon's
   countdown pinned to 5 (blank). Measured: FAILED 27760 = 694x40. Same input
   byte, contradictory outputs — the port's only descriptor input is +63, so
   no src/emotion.rs change can satisfy both rows. Step 4's "emotion_skip
   stays 0/0/40" and step 3's "replace the 5/6 arm" are jointly unsatisfiable
   under the row-freeze rules.

The branch carries the (correct, verified) fix + the new row UNMERGED as
evidence; src/ on main is untouched by it. Numbers in "Measurements".

## Step 1 — the canon ROM watch (measurement)

`possiblyGetBattleEmotion_8015B64` reads the transformation from the battle
NaviStats: `GetBattleNaviStatsAddr` (asm00_2.s:10159) = eBattleNaviStats0
0x0203ce00 (ewram.s:3109) + alliance*0x64, `oNaviStats_Transformation` = 0x2c
(include/structs/NaviStats.inc) → **0x0203ce2c** for the player. The resolved
slot is stored at eStruct+0x10/+0x11 = 0x02035290 (:27341-27342); the blink
countdown is +0xf = 0x0203528F.

Recipe = emotion_syn's canon side (STERILE, PAUSED state, chip b1 cast, A@40,
--disable-bg). `probe.py watch`, 100 capture frames:

| addr | bytes | read |
|---|---|---|
| 0x02035290 | slot halfword | 0x0002 every frame (Unk_32 poke → enum 1 → slot 2) |
| 0x0203528F | blink countdown | **0x00 every frame 0..99** |
| 0x0203ce2c | transformation | 0x00 every frame |
| 0x0203528e | (T122's "beast-out counter" byte) | 0x03 every frame (NOT 0 — T122's halfword poke zeroed it mid-window; harmless there, but its "reads 0" claim was wrong) |

Countdown mechanism read off sub_801CC94 (asm00_2.s:27520-27600) and confirmed
by the watch: the countdown is armed ONLY by a blink event — period timer
r5[0x38] (halfword) reloads 0x14 (20) per blink; when it expires and the state
conditions allow (r5[0x15]==0 needs r5[0x1e]!=0; r5[0x15]!=0 needs
r5[0x17]!=0xff), `GetPositiveSignedRNGSecondary & 1 + 1` arms **1 or 2 blinks**
(r5[0x1d]), each 12 frames (r5[0xf] = 0xc at :27550-27551, decremented at
:27557-27566, reload at 0 while blinks remain). While the PRE-decrement
countdown has bit 1 set (:27567-27570 `mov r0,#2; tst r0,r1`) the 0x20-byte
blink overlay pattern byte_801CDA4 → byte_30016D0 is queued (:27571-27574).
The draw gate blanks the window at countdown 5/6 only
(asm00_2.s:27648-27652) = 2 frames per 12-frame blink.

Per-frame countdown/slot table on the descriptor route: countdown 0x00 and
slot = whatever the enum/transformation resolve to, for ALL 100 frames — the
blink never arms on this route, so the blanking phases (5/6) never occur in
any compared window.

## Step 2 — reaching the cross state on the descriptor route (measurement)

- `--watch-write 0x0203ce2c` over the same 100 frames: **zero writes** — canon
  never writes the battle transformation byte during the window (battle init
  had already run inside the save state), so a load `--poke` survives.
- Poke `0x0203ce2c:0x0001` alone: slot halfword reads **0x0005** on every
  frame 38..99, countdown still 0x00 → canon draws the slot-5 face on all 40
  compared frames. Cross state reached; the window HOLDS on that face.
- Lesson (measured, dropped): poking Unk_32 ON TOP of the transformation poke
  lands slot **0x000a** — enum 1 → byte_801E6F4[1]=2 → the full-synchro +5
  (sub_801E6A8 asm00_2.s:30975-31001: transformation 1..10 +5 when
  byte_801E6F4[enum]==2) fires on 5→10. The cross row must NOT carry the
  Unk_32 poke its siblings carry.
- Slot 6 = `byte_801E700[2]` (transformation 2), same route, same story; slot
  5's art at off_801CD08[5] = bank+0x780 = FACE_INDEX[5], palette slot*32.
- Where canon writes it: nowhere on this route (watch-write, above). Canon's
  writers are battle-side (cross/beast activation); not chased further — the
  descriptor route only needs the byte to hold, which it does.

## Step 3 — the fix + what it costs (measurement)

Fix applied to src/emotion.rs: the 5/6 early-return arm deleted, slots 5/6
build sprites from FACE_INDEX[5]/[6] and their own palettes exactly like every
other slot (the art/palette come from the landed, verifier-confirmed
assets/emotion.bin — canon bytes only, nothing new).

Harness results (`--only ... --no-gallery`, isolated, frames 40), before →
after the fix:

| row | before (unmodified src/) | after the fix |
|---|---|---|
| emotion_cross (NEW: canon poke 0x0203ce2c:1, rust emotion=5) | FAILED 51240 worst 1281, neg 51884 | **FAILED 23480 worst 587**, neg 24124 |
| emotion_skip (frozen) | PASS 0/0/40, neg 644 | **FAILED 27760 worst 694**, neg 28404 |
| emotion_syn (frozen) | PASS 0/0/40, neg 644 | PASS 0/0/40, neg 644 |
| emotion_face_b (frozen) | PASS 0/0/40, neg 644 | PASS 0/0/40, neg 644 |

Reading the emotion_cross residual (this is the money measurement):
- canon-cross vs canon-calm (probe.py diff, a-start 45, 38 frames): total
  1281/frame, of which **694 inside the face box x0..49/y18..35 and 587
  outside** (y35..160, x≈50..79 — MegaMan's on-field sprite region; flat
  across all frames).
- After the fix our slot-5 face matches canon's upload pixel-exactly (51240 −
  23480 = 27760 = exactly the 694/frame face delta), leaving ONLY the
  587/frame non-face delta = canon's cross-form MegaMan vs our calm one.
  That is a battle-side modelling gap (the descriptor route fixes MegaMan in
  his calm form), out of this ticket's scope by its own rules.

fitted/derived/peeked unchanged at 17/434/146 on every run (no new fitted
constants; the fix only deletes an arm).

## What a follow-up ticket needs (the battle-side scenario)

A 0/0/40 cross-face row needs the port to model the cross transformation in
battle (MegaMan's cross-form sprite and everything else the transformation
byte drives) — then `emotion_cross` (already written on this branch: canon
poke 0x0203ce2c:0x0001, rust descriptor emotion=5, trace scenario
`emotion_cross_full` in tools/states.py) should read 0 with the emotion.rs fix
this branch carries. The 5/6 arm deletion also requires redefining the
`emotion_skip` row (its empty-vs-empty pairing premise dies; e.g. its rust
side needs a different empty-box comparison or withdrawal from the suite) —
that is a row-definition change this ticket was not allowed to make.
