## What was learned without captures (keep, next worker)

1. Ticket cite correction: "sub_801E4954" does not exist; the escape handler
   is **sub_80E4954**, reference/bn6f/asm/asm31.s:94519-94557. It is action
   handler index 2 of the action table off_80E4944 (asm31.s:94540-94548) in
   sub_80E4930 (asm31.s:94509-94516), which is CurAction dispatch of the
   type-4 object id 0x3b (t4_0x3b_80E4910, asm31.s:94495-94507, dispatched
   by CurState): the four handlers are object_dimScreen / object_drawChipName
   / sub_80E4954 / object_undimScreen -- the escape cutscene object.
   sub_80E4954: on first entry (PhaseInitialized==0) runs sub_80C4AEC(+5),
   sub_80E49C4(RelatedObject1Ptr), sub_801E658, then plays one of
   sub_8014446/sub_801443C depending on the alliance byte (GetBattleNaviStatsByte
   0x21), sets Timer=0x3c, PhaseInitialized=4; then, when Param2==0, writes
   CurAction=0x0c and phase 0. So the object's next action 0x0c is the escape
   continuation.
2. Rust side pieces, already present:

     2 window variants ("RESULT and LOSER") -- whether canon's ESCAPE screen

     way, is UNVERIFIED (needs a canon escape capture to read it).
   - src/battle.rs ~3548-3575: start_state==1 (start already at the RESULT
