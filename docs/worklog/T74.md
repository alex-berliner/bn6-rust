## Step 3 — port the cited predicate into MettaurEntry hop/refuse arms -- NOT LANDED (NEGATIVE)

The cite is to `sub_801171C` line 5720, but the *cause* lives in the MettaurEntry's
hop/refuse arms. The cited predicate (cause side) is the three-flag read inside
`MettaurHopReservePanel_8109D08`'s refusal: `is_busy()` (BUSY/CANNOT_SLIDE),
`hop_done=0` write, then dispatch into `sub_801171C` (zero Unk_1b, dispatch on Unk_1c, write CurAction=8).

Reading the rust `MettaurEntry` (src/objects.rs:354-505) for the predicate:

- `think()` gates on `me.is_busy()` at src/objects.rs:399 (METTAUR_ACT_WAIT early-return is
  before, then `if me.is_busy() { return; }` -- src/objects.rs:399-401). The is_busy gate means
  `think()` *cannot fire* while the hop exec's predicate would be true -- the exact opposite of
  what the cited predicate requires.

- `mettaur.hop()` (src/actor.rs:830) similarly refuses when busy. The `RowCheck` arm calls
  `me.hop(0, signum, blocked)` at src/objects.rs:430 -- if the Mettaur is busy, hop refuses and
  returns 0; `hop_done = 0 as u8` is stored at src/objects.rs:430. The `METTAUR_ALIGN` arm
  reads `hop_done` at src/objects.rs:450 and routes to `METTAUR_DECIDE` on refuse.

So in rust the *predicate is already met*: at k=17, if `Action::Appearing` were to fall through
to `Action::Idle` and `is_busy()` were true, the hop would refuse (storing `hop_done=0`), and
`METTAUR_ALIGN → METTAUR_DECIDE` would route forward. **But the `CurAction←8` store never
fires** because `Action::Appearing { .. }` is hardcoded to map to `0x0a` in `oracle_fields`
(src/actor.rs:729), and `think()` is gated by `is_busy()` (src/objects.rs:399) so it never
runs in the appear phase at all.

## Per-frame trace (showing the predicate is already met in rust at k=17 but the store never fires)

```

k=0..16            k=0..16                  0x0a                 0x0a              (initial)
k=17               k=17                     0x08                 0x0a              (0x0a→0x08 in canon; rust unchanged)

k=20..             k=20..                   0x0b (attack)        0x0a              (Mettaur attacks in canon; rust idle)
```

Why canon flips at k=17: the Mettaur's hop exec (CurAction=0x0A, AttackStage=0) ran k=0..16
without moving because its BUSY flag was set by the spawn animation; at k=17 the BUSY flag
clears, the hop exec runs MettaurHopReservePanel_8109D08, `object_canMove` STILL returns 0
(some other flag, possibly METTAUR_SLOT_NEIGHBOUR), so the refuse path fires HopDone=0 and
calls object_exitAttackState → CurAction=8.

Why rust never flips: the predicate `is_busy() == true during appear phase` is implicit in
the actor model (the BUSY flag is set during `Action::Appearing`), but `think()` refuses to
run when busy (src/objects.rs:399) -- which is correct for the *normal* busy case but
wrong for this specific edge case where the BUSY flag should CLEAR at k=17 and the refused-
hop path should fire ONCE. The store `cur_action = METTAUR_ACT_DECIDE` at the appear→decide
transition is *missing*; it should fire on the k=17 frame that the BUSY flag clears.
