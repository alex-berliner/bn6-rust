# T97 — M10 netbattle recon (handshake, chip trade, UI state field, scenario design)

Date: 2026-09-17. Recon-only: no src/, no capture, no harness row. All evidence from
`reference/bn6f` (read-only). Deliverable: `docs/coverage/netbattle.md`.

## What I measured (greps + csrc, ~20 commands)

1. Word-boundary SIO grep: SIO registers (0x4000120-0x4000128) appear ONLY in
   `reference/bn6f/asm/libs.s` (plus literal-pool refs from asm38.s). libs.s = full serial
   library: cable SIO driver at the top (0x81440D8+), Wireless Adapter "rfu" stack below
   (rfu_initializeAPI at libs.s:5087, rfu_REQBN_softReset_and_checkID, rfu_NI_* ...).
2. Handshake chain: start.s:222 registers sub_3005E2C at boot → sub_3005E2C (asm38.s:358-391)
   installs IRQ 0x18→libSIO814469C (libs.s:799-807: timer3 stop/reload + libSIOControlStart)
   and IRQ 0x1c→sub_81446AC. libSIOControlStart (libs.s:896-905) = SIOCNT |= 0x80 (start bit)
   — this is the SIO init. Wireless side: sub_813D648 (asm37_0.s:3822-3831) wraps
   rfu_REQBN_softReset_and_checkID, returns r0==1.
3. Session machine: cb_80395A4 (asm03_1_1.s:1309-1346) on eS200A290, 6-entry jump table at
   off_80395C8, dispatch byte +0x00, inner sub-state byte +0x01. sub_8039AB8 polls
   sub_81465BC (bl 1977, nonzero=connected→state 8); sub_8039AE4 polls sub_813D648
   (zero→fade out). sub_8039B0A (asm03_1_1.s:2018-2065) = exchange step: sub_8146588 (2021),
   sub_814695C (2024, arms 8-byte NI ring + flag 0x200FE62), sub_803C418 (2025),
   sub_81469BC (2030), sub_81465BC (2031).
4. Payload write: sub_81469BC (libs.s:5704-5722) appends a u16 to NI send struct
   unk_2010150: low→byte_201015B (+0x0b, line 5713), high→byte_201015C (+0x0c, line 5715).
   The u16 comes from sub_803C418 (asm03_1_1.s:6884-6902): word_2006770, seeded by
   sub_803C40C from GetRNG, recomputed unless MainJumptableIndex==0x18.
5. UI field: BattleSettings is a SINGLETON at 0x0200AF60 (getBattleSettings_200AF60,
   asm03_0.s:14538-14542) — the ticket's "first BattleSettings record" premise does not
   hold; there is one record. background byte at +0x4 = 0x0200AF64, writer
   battleSettings_setBackground (asm03_0.s:14589-14596, strb at 14594 = the SCOPE M1 cite).
   Visible setter callers: asm03_0.s:14617, asm33.s:16529 (near initBattleStructsAndVram at
   asm33.s:16406).

## NEGATIVE (named, per acceptance)

- No netbattle-named symbol exists in the fork: word-boundary grep netbattle|versus|trade
  over reference/bn6f/asm/*.s hits only the in-battle ChipTrader (asm00_1.s:5694,
  asm03_2.s:6901) — a different thing. "Where the handshake arms" for the UI = which caller
  writes BattleSettings+0x4 with the netbattle value: NOT cited; needs a two-instance
  capture with --watch-write 0x200AF64. The two visible callers are candidates, not proof.
- The exchanged u16 (word_2006770) is RNG-seeded; whether it is the traded chip
  id/code pair or a session sync token is UNPROVEN. The chip-selection step that would
  write an id/code into the payload was not located within budget. Next worker: trace
  sub_8049D7C (called from sub_803C418) and the handlers consuming the received
  unk_2010150 payload.

## Frame numbers: deliberately absent

The ticket's scenario asks for frames, but frames require two-instance capture, which is
exactly what mgba_capture.c (off-limits) blocks. netbattle.md §5 therefore defines the
scenario as events + watch addresses (0x4000128 bit7, 0x201015B/C, 0x200FE62, 0x200AF64)
with a proposed row shape and a negative (single instance must take the fade path,
asm03_1_1.s:1979-1984). Follow-up ticket measures the frames once link capture exists.

## Ideas tried and dropped

- Case-insensitive grep "sio" → noise ("colliSIOn"); word-boundary/register-address grep
  found the real sites. 
- ChipTrader symbols → in-battle trader, unrelated.
- asm38.s "chip" grep → nothing; the trade lives in the asm03_1_1.s session machine +
  libs.s NI layer, not in the IWRAM battle module.
- asm33.s looked promising for netbattle init but is map-script battle init; kept only the
  setter-call cite at 16529.
