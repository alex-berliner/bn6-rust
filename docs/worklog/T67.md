## Step 2b — but the tail is CONDITIONAL: battle_full does NOT show it

T63's store table: "no store to 0x0203a9d0 **after canon frame 303**" — which permits stores at
canon 304..313 (k=293..302), where the tail would sit. T66 read it as a 248-frame hold. Two

RESULT: **the tail does NOT fire.** WP log: last Timer store is the underflow
`frame=303 old=0x0000 new=0xFFFFFFFF at=0x08017586` (matching T63's "canon frame 303 (k=292)"
exactly); NO store lines after it. Value bin (--watch, lossy-proof): frames 295..302 countdown

- PAUSED route (STERILE+PAUSED+ALIVE+Start@10): phase INIT fires -> tail 9..0 (measured f138..147)
- battle_full (REAL+PAUSED+custom-screen script): phase INIT does NOT fire -> sentinel holds

The gate must sit on the dispatch path before JumpTable80EA7B0 — the only branch sites are
playerAI_update_80EA734's early-outs: battle_isBattleOver, GetAIData_Unk_44_Flag & 0x8600 ->
sub_801056A(0,0)+return (NO jumptable dispatch), & 0x80000 -> object_setAttack0(0x49)+return.
Which condition differs between the scenes is NOT resolved (candidate: the custom-screen episode
in battle_full's script sets an AIData+0x44 bit; the PAUSED route never opens it). Ideas for the
follow-up: capture AIData+0x44 (player AIData block ~0x020340xx, +0x44) on both scenes, or
--trace-pc 0x080EA764 (the dispatch site) to see whether the dispatch itself stops.

MODEL CONSEQUENCE: the tail is real, attributed, and reachable on the PAUSED route (the mettaur
