## Step 2 — the descriptor write

Per the ticket, add `name=isCustGaugeFullAndBattleLive_800A21C`, `gauge=0x4000`, and a new
`gate=` line to the gunner row's existing `GUNNER_ROW` dict. Two problems with the
straightforward `buf[18] = 0x4000` path:

1. `gauge` is FIXTURE.md +18, **u8** (FIXTURE.md table; src/fixture.rs:203, `pub gauge: u8`).
   `bytearray[18] = 0x4000` raises `ValueError: byte must be in range(0, 256)`. Every existing
   row's `gauge` is 0 or 1 (BANNER_ROW/BUSTER_ZERO/CHIPUSE_ZERO/FIELD_ROW/FIELD_ZERO/GUNNER_ROW/
   OPEN_ROW/RESULTMATCH_ROW/RESULT_ROW/WARP_ZERO/ZERO_ENEMY*/gauge=1: CARDNAME_ROW/CURSOR_ROW/
   CUSTMATCH_ROW/HUDMATCH/ISOLATED_*/WINDOWCLOSE_ROW); a `& 0xFF` mask on
   `fixture_cheats`'s gauge line preserves every one of them byte-for-byte and lets the new
   0x4000 round-trip to 0x00 — the descriptor-only write the ticket promises.
2. `name` and `gate` are not FIXTURE.md fields; `fixture_cheats` only reads
   FIXTURE.md's published offsets via `descriptor.get(<key>, default)`, so unknown keys
   are silently ignored. They land as pure documentation on the harness-side dict (a
   future src/ gate wiring can lift them without re-deriving the gate symbol).

The minimal fixture_cheats change is one line: `buf[18] = descriptor.get("gauge", 0) & 0xFF`.
Census confirms every other row's gauge is in 0..1 so no other row moves; verify_rows over
the full twelve-row guard list confirms the same empirically in step 4.
