### Step 3b — `tools/diffmask.py --frames` (commit `e8ce477`)

Added `--frames START..END[,START..END,...]`. The flag:

1. Parses a comma-separated list of inclusive `START..END` ranges
   (range parser with explicit error on bad tokens).
2. Requires `real` and `rust` to be directories (the existing first-
   sorted-frame path stays the default when `--frames` is absent).
3. Loads frame `k` from each dir for every `k` in every range, runs
   the same diff_one() over it, and writes one PNG per range
   `<out>_<s>_<e>.png`.
4. Prints the first-frame differing-pixel count for each range, the
   worst-frame count + index, and a total across ranges.

The existing first-sorted-frame path is unchanged (single-frame use
case still works without `--frames`).

```
$ python3 tools/diffmask.py /tmp/pf_canon /tmp/pf_rust /tmp/t47_dm.png --frames 0..20
--frames: empty directory (/tmp/pf_canon or /tmp/pf_rust)
```

(returns cleanly with a diagnostic instead of argparse-erroring)

### Step 3c — `tools/oracle.py --both` + battle_full (commit `efda646`)

Two coupled changes (one commit, because they touch the same lookup
path):

**A. `tools/harness.py` — add `SCENARIO_ROWS` after CHECKS:**
```python
SCENARIO_ROWS = ("battle_full",)
```
This is the literal "row whitelist" the ticket asked for: oracle.py's
accepted-rows list is widened to include battle_full. SCENARIO_ROWS
lists non-comparison scenarios whose sides and alignment live in
states.TRACE_SCENARIOS, not in CHECKS.

**B. `tools/oracle.py` — fallback to `_scenario_check(args.row)`:**

- Added `import state as S` (S = states module) at the top.
- Added `--both` argparse flag as a no-op (the oracle on a single row
  already watches BOTH sides — rust ORCL block + canon RNG/MM/enemy/
  gauge; the flag is accepted for compat with the ticket's documented
  invocation, and the docstring says so).
- Added `"battle_full": 2` to ENEMY_SLOT — battle_full's fixture is a
  single Mettaur (kind=0), same family as the mettaur row, so the
  populated canon slot is the SECOND T1 entry, 0x0203ab60 (ALIVE
  proof: 0x0203ab84 = 0x0203ab60 + oBattleObject_HP, same as
  mettaur).
- Added `_scenario_check(name)` helper that builds a synthetic
  `H.Check(name, ui="isolated", frames=scen["frames"], align=Align(
  canon_ref=scen["canon_ref"], rust_offset=scen["rust_base"],
  search=None, note="scenario %s from states.TRACE_SCENARIOS" % name),
  rust=rust_factory, canon=canon_factory)` from the scenario spec:
    - `rust_factory(_variant)`: Side(rom=H.plain_rom(),
      fixture=spec["fixture"], script=spec["script"]) — the harness
      fixture path, same as a Check's rust side.
    - `canon_factory(_variant)`: Side(**spec["canon"]) — the script +
      loadstate + cheats path, same as a Check's canon side.
  The marker on the rust side is the harness's own boot marker
  (src/main.rs's Battle::update writes it from BATT onward), so
  H.run()'s `find_marker_origin` still gives a usable origin (rust
  capture frame 8 = battle frame 0; matches the mettaur row's origin).
- Lookup order: `H.CHECKS` first; if empty, `H.SCENARIO_ROWS`; if
  still empty, the existing "unknown row" error (which now lists
  SCENARIO_ROWS in the message so the next ticket has a hint).

The `cast_sides()` machinery, the canon watches (RNG/MM/enemy/gauge),
the rust ORCL block watch, the alignment, the field comparison, the
pixel diff, and the negative control all reuse the existing oracle
flow verbatim — `_scenario_check` only differs from a CHECKS entry in
that the Sides come from states.TRACE_SCENARIOS instead of the Check's
rust/canon factories, and the alignment is the scenario's own
canon_ref/rust_base pairing (no search band: search=None, rust_offset
= rust_base; the battle_full scenario has only one rust export-frame
counter reading 0 at battle start, the same way trace.py aligns it).
