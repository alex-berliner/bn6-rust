## Step 1 — read the tables out of the ROM (measurement, no capture)

Read directly from `/tmp/bn6f_sterile.gba` bytes (af13c206…43e4154cf3, 8388608 B),
file offset = addr − 0x08000000, and cross-checked against the disassembly.

**Ticket-premise correction.** The ticket calls `byte_801E6F4` "the 23-entry
enum→slot table". The ROM says otherwise:

- `byte_801E6F4` @ **0x0801E6F4** (asm00_2.s:31045) is **6 entries + 2 pad bytes**
  `[0, 2, 3, 1, 5, 4]` (pad `0,0`). It maps the **emotion ENUM**
  (`possiblyGetBattleEmotion_8015B64`'s res0, asm00_2.s:15122-15174) to a face
  slot. Its two consumers index it with the enum (`ldrb r0, [r2,r0]`,
  asm00_2.s:30970/30984/30997/31011/31033 — stride 1).
- The **23-entry table next door is `byte_801E700` @ 0x0801E700**
  (asm00_2.s:31049): 25 entries + 3 pad
  `[0, 5, 6, 7, 8, 9, 5, 6, 7, 8, 9, 0x14, 0x14, 0xF, 0x10, 0x11, 0x12, 0x13,
  0xF, 0x10, 0x11, 0x12, 0x13, 0x16, 0x16]` (pad `0,0,0`). It is indexed by the
  **TRANSFORMATION** byte (the r1 second return of possiblyGetBattleEmotion,
  read at asm00_2.s:30966 `ldrb r6, [r2,r4]`), not the emotion enum — with
  post-adjustments: for r4 in 1..10, if `byte_801E6F4[enum] == 2` (Unk_32 set,
  full synchro) slot += 5; for r4 == 11/12, if `byte_801E6F4[enum] == 3`
  (Anger) slot += 1 (asm00_2.s:30975-31001).

**Skip-range (5/6) entries.**
- `byte_801E6F4[4] = 5` — but enum 4 is **unreachable**:
  `possiblyGetBattleEmotion_8015B64` (asm00_2.s:15140-15166) only ever returns
  5 (Unk_36≠0 or Mood==0), 3 (Anger≠0), 1 (Unk_32≠0), 2 (Mood==0xff), 0. So no
  poke on the AIData bytes can ever land a slot in the skip range through the
  enum table. This is the ticket's "one enum that lands on a skip slot" premise
  failing: **there is no such enum**.
- `byte_801E700[1] = 5`, `[2] = 6` — reachable only via a non-zero
  transformation byte, i.e. a Beast Out/Cross state, not a poke recipe on this
  route.
- The skip range is therefore only reachable in the compared window by the
  draw gate's own byte: `drawEmotionWindow_801CDEC` reads eStruct2035280+0xf =
  **0x0203528F** and skips 5/6 (asm00_2.s:27647-27652). T108 already measured
  byte=5 there → the face vanishes, 694 px/frame in x0..48/y18..34. The skip
  arm pokes 0x0203528F. On the emotion_syn route nothing writes that byte in
  the window (T105 pass-4 watch: 0x00 for 80 frames; its only writers are the
  blink updater sub_801CC94, asm00_2.s:27551-27566), so a load poke survives —
  verified by measurement in step 2.

**Slot coverage.** `off_801CD08` @ 0x0801CD08 (asm00_2.s:27580-27603), 23
pointer words, read from ROM, deltas from dword_872D814:
`[0x0000, 0x0180, 0x0300, 0x0480, 0x0600, 0x0780, 0x0880, 0x0980, 0x0a80,
0x0b80, 0x0c80, 0x0d80, 0x0e80, 0x0f80, 0x1080, 0x0780, 0x0880, 0x0980,
0x0a80, 0x0b80, 0x1700, 0x1700, 0x1800]` — byte-identical to the landed
`src/emotion.rs` FACE_INDEX. Slots 15..19 alias 5..9, 21 aliases 20; slots 5/6
HAVE art (0x780/0x880) but the draw gate never lets them on screen; the landed
`assets/emotion.bin` bank covers all 23 slots (0x1900) and all 23 palettes
(0x2e0). Palette check from ROM (dword_872F114 + slot*32): slot 4's palette
DIFFERS from slot 2's, as do all of 0,1,3,4..22 — every drawn face has its own
palette.

**Chosen pokes.**
- `emotion_face_b` (drawn face, own palette): AIData.Unk_36 `0x020340B6:0x0001`
  → enum 5 → slot 4. T105 already measured this poke face-only (694 px/frame,
  no panel tint, not consumed). Rust side: descriptor `emotion=4`
  (FACE_INDEX[4]=0x0600, palette slot 4 ≠ slot 2).
- `emotion_skip` (skip arm): gate byte, aligned halfword poke
  `0x0203528E:0x0500` → little-endian bytes 0x0203528E=0x00
  (eStruct+0xe, stored transformation — 0 is its calm value), 0x0203528F=0x05
  (eStruct+0xf, the gate byte → draw emits nothing). Rust side: descriptor
  `emotion=5` (src/emotion.rs builds no sprites for 5/6).

## Ideas tried / dropped

- *Skip arm via enum*: dead — enum 4 is unreachable from
  possiblyGetBattleEmotion's arms; documented above. The gate-byte poke is
  T108's own measured route, not a widening.
- *Skip arm via transformation poke* (byte_801E700[1]=5): rejected — needs
  the NaviStats transformation byte, a different struct from T105's recipe,
  and the row would then also exercise cross-face art paths the ticket
  didn't ask for; the gate byte isolates the skip behaviour exactly.
- *Mood→0xff for slot 3 as face_b*: dropped in favour of Unk_36 (slot 4) —
  T105 had already measured the Unk_36 poke face-only; Mood would have needed
  its own poke-effect A/B.

## One line of mechanism / one line unverified

Mechanism: canon picks the face from live AIData bytes through byte_801E6F4
(enum→slot) or byte_801E700 (transformation→slot), uploads slot art +
per-slot palette every frame, and the draw gate at eStruct+0xf=0x0203528F
suppresses the whole window for slot values 5/6 — the port takes the already-
resolved slot from descriptor +63 and reproduces both a drawn face (slot 4)
and the skip (slot 5) byte-exactly.

Unverified: the remaining emotion slots never compared to a pixel (bank slots
1, 6..22 — no reachable poke on this route drives them; slot 4 and the skip
are now proven), and the emotion **counter** window, which is its own item.
