# D10 — Name the disassembly's unnamed struct fields from evidence we already hold

**Why.** The disassembly declares 1,058 struct fields and 479 are still `Unk_<offset>`. Source
comments and `// bn` notes name many of them in passing; those names never reach
`reference/bn6f/include/structs/*.inc`, so the disassembly (and the C generated from its
types) keep calling them `Unk_54`. Today's lift of the read-only rule allows naming where
the evidence is concrete; the gate is the rebuild to the ROM's sha1.

**Setup.**
- worktree: `/tmp/bnwt/d10-fieldnames` on `wt/d10-fieldnames`
- baseline sha1: `0676ecd4d58a976af3346caebb44b9b6489ad099` (both `bn6f.sha1` and `sha1sum`)
- reference/bn6f is symlinked to main checkout (read it; do not commit there)
- `make -j$(nproc)` rebuilds to the same sha1: confirmed

## Plan

1. Collect evidence from `src/*.rs`, `reference/bn6f/asm/*.s` `// bn` notes,
   `docs/coverage/*.md` and `docs/recon/*.md`. Each piece of evidence either names an
   Unk_<offset> outright (rename), is hedged/inferred (leave Unk_, list), or only comments
   on a NAMED field (skip).
2. Build `tools/field_names.py` to scan, parse and emit the rename table.
3. Apply renames across the disassembly's `include/structs/*.inc` and `include/rom_structs/*.inc`,
   then `asm/*.s` and `data/*.s` (every use). The offset comment must stay (`// loc=0xNN`).
4. Append each (old, new, evidence) to `reference/bn6f/docs/renames.md`.
5. Rebuild, compare sha1; mismatch or assembler error reverts the pass.
6. `bash tools/retype_if_stale.sh --force`, report the named-field-access count delta.

## Evidence to gather (Step 1)

Surfaces that name fields outright in `Unk_<NN>`-form (so a rename can be applied):

- src/*.rs: comments that say `oAIData_Unk_68` IS X (we already see some via ticket text).
- `reference/bn6f/asm/*.s` `// bn` notes: lines like "// bn: oAIData_Unk_54 is X".
- docs/coverage/*.md and docs/recon/*.md: any `Unk_<NN>` mention with a stated role.

A field is renamed only if a sentence STATES the role outright. Hedged language
("probably", "likely", "looks like") keeps it as `Unk_`.

### Step 2 — tools/field_names.py

Builds the table from `RENAMES` (a list of `(struct_path, struct_macro, old, new, evidence)`);
the macro name is needed because AIData.inc declares THREE structs (`ai_data_struct`,
`ai_state_struct`, `ai_attack_vars_struct`) and they all have fields called `Unk_00`/`Unk_10`.
`apply` rewrites:
  - the bare field declaration inside the chosen macro's `&.endm` body
  - every `o<Struct>_Unk_<offset>` use across `asm/*.s` and `data/*.s`
…then appends a `## D10` section to `docs/renames.md`.

### Step 3 — Apply

`python3 tools/field_names.py apply` rewrites 13 fields. The biggest mover is
`oAIAttackVars_AttackWait` at 2,727 use sites; the smallest is
`oObjectSprite_CurAnim` at 7.

### Step 4 — Rebuild

### Step 5 — Retype

`bash tools/retype_if_stale.sh --force` regenerates the decompiled C from the new types
(stamp `c85117df…` -> `d80ea2e3…`). 7,490 references to the new names appear in 2,081
decompiled .c files; the named-field-access count rises accordingly.
