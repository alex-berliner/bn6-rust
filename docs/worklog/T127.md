## Step 1 (restated for the record) — canon's loss condition (no capture)

`showResultWindow_802C34E` (asm03_0.s:12353) does NOT choose the variant. All four
ending sequencer states call it with the same base `unk_2035260`
(asm00_1.s:13385/13976/14385/14838 -- four wrappers sub_80094B6/8009916/8009C06/
8009F3A, one per ending kind: win / lose / escape / time-out family). The routine
indexes the table by the battle state's own `oBattleState_Unk_0d` byte:

- `ldrb r1, [r1,#oBattleState_Unk_0d]; mul r1,#0xc; add r0,r0,r1`
  (asm03_0.s:12435-12441) -- a 12-byte record per ending kind; the record's byte 0
  (→ dword_20364C4) selects one of three tile sets at off_802C434
  (dword_8731DF4/8732154/87324B4), i.e. the window variant.

**The won/lost store is `oBattleState_Unk_0d`, written exactly once, at
asm00_1.s:9641** (sub_80079A8, the battle-end dispatch):

```
bl GetBattleEffects            // asm03_0.s:14488: battleSettings effects word
mov r1,#8; tst r0,r1; bne ...  // bit 0x08 = "a combatant was deleted"
  -> sub_803DD60               // asm03_1_1.s:9414: returns 1 when
                               //   eLinkState+0x48 & 3 != 0 (the player-deleted
                               //   live gate) or jump offset 8
strb r0, [r5,#oBattleState_Unk_0d]   // asm00_1.s:9641  (0 = win, 1 = lose)
```

So: effects bit 0x08 fires the dispatch; sub_803DD60 answers "did the PLAYER go
down" from `eLinkState+0x48 & 3`; 0 → win record, 1 → lose record. The upstream
lever is the player object's HP word `oBattleObject_HP` (+0x24 → **0x0203a9b4**,
BattleObject.inc:105, object base 0x0203a9b0): HP 0 → defeat dissolve → SEQ_10
path → dispatch reads 1 → LOSER record. Sequencer state the LOSER window enters
through: the lose wrapper (the 13976 family, sub_8009916) shows the window on its
first run (`oBattleState_Unk_03 == 0`) then drives `resultWindowDriver_802BD60`
each frame; on driver return 0 it stores Index_01 = 0x14 (leave).

Our port already mirrors this shape: src/battle.rs:2889 transitions
SEQ_08 → SEQ_10 when `self.megaman.is_defeated()` (vs SEQ_0C win), and :3232
picks `results::LOSE` on the same predicate. The question this ticket measures is
only whether the LOSE arm's *pixels* match canon's.
