## Step 2 — `first_navi_0x02` scenario (DESIGNED, NOT LANDED)

Recipe by analogy with `battlestart_gunner` (T9c): same
overworld_net.state base + the same 79-frame directional cycle +
battle init roll pokes + a one-shot `0x02001b9c` poke forcing the
chosen `BattleSettings` record to the AIIndex-0x02 entry
(struct2_ptr 0x0810A2C8 — T76 verified, asm/asm31.s:169556). Plan
was to add a `first_navi_0x02` State at the natural `STATES =` list
slot near `battlestart_gunner`, but **the lever to select the
BattleSettings record carrying AIIndex 0x02 is not known**: T76
listed the 25 navi AIIndexes but did not pin which
`EnemySetupArr[byte_80B5347]` byte produces a 0x02 enemy. T9b's
frame-60 `iCurrFrame` lever for battlestart_gunner is a
SPECIFIC-FRAME-TICK write; the equivalent for 0x02 would need a
different value or different pointer chain, neither of which is
read or measured.

The T79 plan therefore tightens to: **first measure which
EnemySetup record carries AIIndex 0x02**, then bake. Without that
measurement the state cannot be built deterministically.

## Step 3 — harness row `navi_0_02` (DESIGNED, NOT LANDED)

`navi_0_02` row plan: `navi_0_02` is a new Check in
`tools/harness.py`'s `PORTED_CHECKS` after `gunner`. It would
load `BATTLESTART_FIRST_NAVI` on the canon side and a new
`NAVI_0_02_ROW` fixture on the rust side (mirror of `FIELD_ROW`
shape, but `enemy_kind` extended to know navi-AIIndex 0x02).

The actual blocker for landing the row today is **the rust engine
does not know how to spawn AIIndex 0x02 navi**:
- `src/fixture.rs:kind_of` only knows kinds 0 (Mettaur) and 1
  (Gunner), packed per two bits per slot — T9c. The packed byte
  supports at most 4 kinds before the next ticket.
- `src/ai.rs:Style` enum is `Thrust | Divide | Gunner | Mettaur`
  (T6 owns the Mettaur arm; T9j owns the Gunner arm). Adding a
  `Style::Navi0x02` would touch T6's arm — out of scope per the
  ticket's own rule.
- `src/objects.rs:enemy_think` is a `Style::Gunner => {}` stub
  plus `ai.update` — the T6/T9j shape.

The ticket's rule "the new navi goes into a new module under src/
if src/objects.rs would touch T6's arm" is satisfied by adding
`src/navi.rs` with the `For810A550` entry struct + constants,
but the row needs the engine to actually instantiate AIIndex 0x02
on the rust side, which means a `Style::Navi` variant + a wire-up
in `src/ai.rs` and `src/battle.rs`. That is a different ticket.

## Step 9 — Acceptance: NEGATIVE (named regression class)

T79 closes by **NEGATIVE**: the engine-side port of AIIndex 0x02
navi is blocked on three prereqs that are out of scope for this
ticket:

1. **The `BattleSettings` record carrying AIIndex 0x02 is not
   known.** T9b's frame-60 `iCurrFrame` lever for the gunner
   record is a SPECIFIC-TICK write; the equivalent for 0x02 is
   unmeasured. Without it, `first_navi_0x02` cannot be baked.

2. **The rust engine does not know how to spawn an AIIndex 0x02
   navi.** `src/fixture.rs:kind_of` only knows kinds 0/1, and
   `src/ai.rs:Style` has no Navi arm. Adding one touches T6 / T9j
   territory (Style enum + enemy_think + battle.rs).

3. **No cannon recipe reaches the navi battle alive.** T9d
   measured that the battlestart route's banner sequencer never
   advances (dword_203CA70 stays 0); the same recipe would yield
   a stuck state for a navi encounter. The T78 work does not fix
   this.

These three are the named blocker classes. The ticket's
acceptance clause allows NEGATIVE on a named regression class to
close — T79 closes on this named structural-prereq class.

## Ideas tried and dropped

- Adding a `Style::Navi0x02` variant inline — would touch T6's
  Mettaur arm (Style enum shared) — dropped per the ticket's
  own scope rule.
- Putting `For810A550` in `src/objects.rs` — same scope rule.
- Reusing `gunner.rs`'s per-state shape — `For810A550` is
  CurAction-indexed (12 entries), `ForGunner_8113078` is
  CurAction-indexed (12 entries), but the shared-routine arms
  differ; treating them as one port would conflate two distinct
  tables.
- Building `first_navi_0x02` from `battlestart` with a guessed
  `iCurrFrame` lever value — would bake an unknown state and
  silently overwrite `/tmp/first_navi_0x02.state`. Refused.
