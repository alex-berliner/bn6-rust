## Step 3 — the three arms (asm00_2.s read from disk; decomp via csrc.py first)

`blindVisualHandledHere_8016934` @0x08016934 (asm00_2.s:16821-16889);
`object_getFlag` (asm00_2.s:21629-21630) = `*(CollisionDataPtr + 0x3c)`:

- **Prologue** :16824-16829 — unless `battle_isTimeStop`, re-assert bit 1
  (OBJECT_FLAG_VISIBLE) of the object-header flags every frame.
- **Arm A, DEAD out** :16831-16834 — own flags & 0x100 → return. Everything
  alive reaches the arms below.
- **Arm B, INVIS|FLASHING blink** :16835-16845 — own flags & 0x202, then the
  CollisionData chase + `ldrh FlashingInvisTimer` :16839 and `lsr r0,r0,#2;
  bcc` :16840-16841: carry = original bit 1, so hide iff timer bit 1 set —
  **this is INVIS_HIDE_BIT's true cite; the "16787" in src/actor.rs:421 was
  stale and is re-derived to :16839-16841 in this branch** (the sibling stale
  range "16796-16806" in show_with_underlay's comment → :16835-16845).
- **Arm C, the cross-alliance clear** :16846-16870 —
  `oBattleState_Unk_0d ^ Alliance != 0` (:16849-16852, cross-side objects
  only) → `battle_findPlayer(Alliance ^ 1)` (:16853-16856) → its flags &
  **0x2000** (:16861-16865) → clear OBJECT_FLAG_VISIBLE on THIS object
  (:16866-16869). Render suppression only. This is the arm the ticket ports.
- **Arm D, same-side** :16871-16886 (`loc_8016998`) — CurAction != 0 and
  AIData ActorType == 2 → `dispatch_801DA48(5)` unconditionally and
  `dispatch_801DACC(5)` if OWN flags & 0x2000. Measured pixel-neutral on this
  scene (step 2: no pixels outside the Mettaur box), so the port omits it.
- **Who clears BLIND**: the tick in `sub_800E730` (object.s:5511-5526):
  `BlindTimer -= 1` :5512-5514; when the decremented value fails signed
  `bgt` :5515 (0 → 0xFFFF), `object_clearFlag(0x2000)` :5517, zero the timer
  :5519 and [+0x4c] :5520; the chip path (arg bit 0x20) re-sets it :5521-5532.
  NOT modeled in our port (the row pokes 0xffff, outliving the window).

## Step 4 — the port (committed, red)

- `src/actor.rs`: `OBJECT_FLAGS_BLIND: u16 = 0x2000` (CollisionData.inc:16,
  the ObjectFlags1 enum at :145), `COLLISIONDATA_BLIND_TIMER: u16 = 0x20`
  (:134), `COLLISIONDATA_OBJECT_FLAGS1: u16 = 0x3c` (:145), all tagged;
  `#[no_mangle] pub static mut BLIND_POKE_MAILBOX: BlindMailbox {object_flags1,
  blind_timer}` (two halfwords mirroring the canon fields the gate reads);
  `opposing_player_flags()`; the cross-alliance arm at the top of
  `Actor::show` (now `(frame, dy, opposing_flags: u16)`); stale cite fixed.
- `src/battle.rs`: the enemy loop (:~5180) hands `actor::opposing_player_flags()`
  to every enemy's draw — the one call site the ticket allows.
- `tools/harness.py`: ONE new row `blind` (mettaur row's route/sides +
  `pokes_at` at frame 40 both sides; canon pokes 0x0203852c/0x02038510, rust
  pokes the mailbox at **0x020002fc**/+2 — `nm BLIND_POKE_MAILBOX` on this
  tree's ELF; rows poke literals like every fixture address, and a moved
  address fails loudly); Align canon_ref=40 (the poke IS the event), search
  range(26,39), frames=90, isolated, --disable-bg.
- **Mailbox placement trap:** a plain (immutable, zero-init) static lands in
  ROM (.rodata, nm VMA 0x08049a2c) where a poke cannot reach; `static mut` in
  plain `.bss` lands in EWRAM (gba.ld `.bss (NOLOAD) > ewram` :61-68). A
  second dedicated `.ewram.*` section was rejected — main.rs's BATTLE_MARKER
  doc measured that such sections reorder and can break the fixture's
  0x02000000 contract; .bss layout does not touch the marker section
  (BATTLE_MARKER verified still at 0x02000000 after the build).

### The LTO fold trap (cost most of a day — read this first)

First row run: **FAILED 69,987 px** and `objdump -d | grep 2002fc` found ZERO
hits: fat LTO proved the program never writes BLIND_POKE_MAILBOX (the poke is
emulator-side, invisible to the compiler) and folded the volatile read to 0.
The fixture block survives the same fold only because it shares
BATTLE_MARKER's array, which the program DOES write every frame. Fix
(committed): route the address through `core::hint::black_box` so the load's
address is opaque. After the fix the poke is live (see step 5). Anyone adding
a second poke-fed mailbox: black_box the address or hang it off
BATTLE_MARKER, or LTO will silently zero your gate.

Diagnosis (diffed ours poked-vs-unpoked at captures 43/50/60/80/100): the
residual is ~308-396 px/frame INSIDE the Mettaur's own box (bbox x 168-197,
y 90-119) — part of her sprite still draws. Canon's OBJECT_FLAG_VISIBLE clear
suppresses the WHOLE object's OAM; our `Actor::show` early-out only skips
`show_with_underlay`'s output, so a second draw contributor (shadow layer or
another commit path in the enemy draw) survives the gate. **Next worker:
find the second contributor that draws the remaining ~half of the Mettaur
(suspects: the enemy shadow / any per-enemy sprite commit outside
Actor::show in battle.rs's draw; diffmask ours poked-vs-unpoked and match the
surviving pixels to a draw call), and re-point the gate so it suppresses
everything the header flag would.** Do NOT touch the AI: step 2 proves the
render arm alone is the subject. The frame timing needs no work: first
divergence lands on the same presented frame on both sides (canon k=1, ours
first=2 in a window starting one frame earlier — same absolute frame 41), and
the poke-at-40 recipe is identical on both sides.

Negative on the red row read 70,487 (not blind) — once the row is green the
frame-shift negative must stay nonzero; the window carries the attack cycle,
the wave and the 114 hit, so it cannot go blind.

Ideas tried and dropped:
- Dedicated `.ewram.blind` link_section — rejected (BATTLE_MARKER reorder
  risk, measured in main.rs's doc).
- Immutable static mailbox — rejected (lands in ROM, unreachable by poke).
- Reading the mailbox in update() instead of draw — moot: the presented-frame
  timing already matches canon; the defect is coverage, not phase.
