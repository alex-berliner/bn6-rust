## What is unverified

is exact on this build. Widening the asset to deliver another family-0x21
chip (no other row exists in ChipDataArr_8021DA8 today — verified by
sweep `attack_family: 0x21` over all 411 struct blocks) would re-run
AirShot's pose and barrel on the new chip too, which would be correct
if the new chip shares sub_80EC884's behaviour. The src/fixture.rs:547
comment naming `CHIP_AIRSHOT` stays: the deck-entries list there is a
demo-custmatch / demo-cardname scenario fixture, not a per-id index of
an amount, and the literal is in a `//` doc comment.
