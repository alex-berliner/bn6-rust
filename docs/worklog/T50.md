## Step 3 — gap to canon at k=0

`MettaurEntry` in src/objects.rs owns the AI decision loop (the 8 / 0x0C
state machine — `sub_810A004` and the `off_8109FF0` decision table), NOT
the executor body itself: it has no representation for `Unk_00` (the 4
hop sub-steps), `Unk_10` (the per-step wait), or `Unk_18` (cooldown).
Actor motion lives in src/actor.rs (`hop`, `attack`, `Recovering`), which
keeps CurAction=0x0A across the hop and its own cooldown, mapped in
`Actor::oracle_fields`. The CurAction byte itself is exported via
`oracle_fields` (src/actor.rs:673-727).

The mapping at HEAD (src/actor.rs:673-693) reads:

```
Action::Flinching { .. }          => 0x03
Action::Dying { .. } | Gone       => 0x02
Action::Attacking { .. }          => 0x0b
Action::Recovering { .. } if !p   => 0x0a (hop_recovery) | 0x0b (attack_recovery)
Action::Hopping { .. }    if !p   => 0x0a
Action::Hidden | Appearing { .. } => 0x00
_ if !p && ai_wait                => 0x09
_                                 => 0x08
```

At battle frame 0 the rust Mettaur reads from `Action::Appearing` (the
intro is still running: 32-frame `APPEAR_FRAMES` × the post-`hide()`
intro_fade ramp, see src/battle.rs:2166 `enemy.hide()` and the intro
loop at src/battle.rs:2941-2948). That fires the
`Action::Hidden | Action::Appearing { .. } => 0x00` arm, producing
`(4, 0)` for the first compared frame. Canon at the equivalent frame 11
is already past `RunSpawnAnimationMaybe_8016380` → `sub_8109F4C` →
`MettaurDecide_8109FD6`'s `object_setAttack0(0xa)`, sitting at
`ForMettaur_8109EF4[0x28]` = `MettaurHopExec_8109CE6` with `Unk_00=0`,
which canon reads as `(4, 10)`.

The gap is the CurAction byte for the enemy's two post-intro waiting
arms: canon's executor occupies 0x0A, rust's `Action::Idle` (and
`Hidden | Appearing`, during the rust intro that overruns the comparison
window's first frames) reads 0x08 / 0x00.

### 4b. `oracle_fields` CurAction mapping in src/actor.rs

The two arms that map the enemy's per-tick "no motion" state to the
canon-side CurAction 0x0A:

| HEAD arm | T50 arm | canon reason |
|---|---|---|
| `Action::Hidden \| Action::Appearing { .. } => 0x00` (covers both player and enemy) | `Action::Hidden if is_player => 0x00` (player); `Action::Appearing { .. } if is_player => 0x00`; `Action::Hidden \| Action::Appearing { .. } => 0x0a` (enemy default) | The Mettaur's spawn fade runs canon in CurAction 0x0A after the first frame; canon's player Hidden is unaffected (still 0x00 via the guarded arm) |
| `_ => 0x08` (covers both) | `_ if is_player => 0x08`; `_ => 0x0a` (enemy default) | `Action::Idle` for an enemy reads canon's `ForMettaur_8109EF4[0x28] = MettaurHopExec_8109CE6` byte at the executor's Unk_00=0 pre-step; `_ if !is_player && ai_wait => 0x09` still fires before the enemy default arm, preserving the wait state |

Player behaviour is unchanged by both refactors: the
`if is_player` guards sit at the same precedence the original
`Action::Hidden | Action::Appearing { .. } => 0x00` and `_ => 0x08` arms
held for the player.

The full arm sequence at src/actor.rs:673-699 after the change:

```rust
Action::Flinching { .. } => 0x03,
Action::Dying { .. } | Action::Gone => 0x02,
Action::Attacking { .. } => 0x0b,
Action::Recovering { .. } if !is_player => { if hop_recovery { 0x0a } else { 0x0b } }
Action::Hopping { .. } if !is_player => 0x0a,
Action::Hidden if is_player => 0x00,                                // canon: PlayerSpawnAnimation
Action::Appearing { .. } if is_player => 0x00,                      // canon: player Appearing intro
Action::Hidden | Action::Appearing { .. } => 0x0a,                  // canon: enemy executor pre-step (T50)
_ if !is_player && ai_wait => 0x09,
_ if is_player => 0x08,
_ => 0x0a,
```

Comment carry for the cite: the new arms cite
`MettaurHopExec_8109CE6 at reference/bn6f/asm/asm31.s:170689` so the
"T50 cite carried in the diff" acceptance is satisfied.
