## Discovery — what "first-pattern routine" actually is

The ticket names `off_80F24D8 / off_80F253C / off_80F25A0 (M6 FOUND; per-AIIndex
via sub_80F2354)`. Reading T76 step 3 + the asm31.s:123323-123356 reader:
sub_80F2354 reads FOUR 25-entry tables, NOT three:

1. `off_80F2410[ai]` = `sub_801A9B8+1` (slot 0x17) — shared damage routine, called first (bx r0, asm31.s:123330)
2. `off_80F2474[ai]` = `nullsub_106+1` (slot 0x17) — per-ai PATTERN routine, called second (bx r0, asm31.s:123336); 22 of 25 are nullsub, only slots 5/10/16 are real
3. `off_80F23AC[ai]` = `off_81068E8` (slot 0x17) — 15-entry CurAction-indexed handler table, passed to `ai_eventuallyRunsAIAttack_801AF44` (asm31.s:123345-123347)
4. `NaviActHandlers_80F25A0[ai]` = `nullsub_106+1` (slot 0x17) — per-ai ACT routine, called last (bx r0, asm31.s:123349); 22 of 25 are nullsub, only slots 0/5/13 are real

So the ticket's "off_80F24D8 / off_80F253C / off_80F25A0" lists the NAVI-SIDE
struct column + act table — those tables ARE FOUND (M6 FOUND), and their
slot-0x17 entries are already ported in src/navi.rs as `NAVI_COL_STRUCT1`,
`NAVI_COL_STRUCT2`, `NAVI_ACT_LEG` (T145). The "per-AIIndex pattern" itself
is the CurAction-handler table at `off_80F23AC[ai]` = `off_81068E8` for slot
0x17, ported as `AI_ARM` (15 entries, T145).

**The "first-pattern routine" therefore = the per-AIIndex CurAction dispatch
into `off_81068E8`'s 15 entries for slot 0x17.** The first arm the row would
exercise is entry 0x08 (CurAction 0x08 = sub_8106924+1, asm31.s:164174),
the AI-tick leg of the AI arm. But the actual attack happens through
`AIThinkTables_8109050[0x17] = ForGunner_8113078` (the think arm), reached
separately from `sub_8108F50`'s CurAction 0x20+0x0A path (asm31.s:169415).

Slot 0x17's `ForGunner_8113078` is already documented in src/gunner.rs's
module doc and partially ported (`gunner_update`, the CurAction 0x0A arm,
`#[allow(dead_code)]`). Wiring it for `Style::Navi` is the new work.
