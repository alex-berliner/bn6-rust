## Step 3 ruling (the negative-case question)

Rule applied: a family is as-data when every BEHAVIOUR-SELECTING dispatch — which arm
runs — reads a record byte. Timing/presentation literals do not select between arms, and
the in-tree precedent is the sword family 0x13 (in AS_DATA_FAMILIES with peeked timing
consts; tools/inventory.py's own block comment says a non-behaviour-selecting id gate did
not even disqualify it). AreaGrab's fitted presentation quartet (77/47/4/3) times one arm;
it does not choose between behaviours. So the fitted literals do NOT block re-admission.
Additionally this ticket removed the family's LAST two id gates, so 0x15 dispatch is now
record-only: family+subfamily at every site. INVISIBL_FRAMES (0x68) is a record byte —
177's AttackParam1 (:5504) — so the const was DELETED and the arm now reads
chip.params[0] (same path barrier_hp/barrier_palette already use). The AreaGrab quartet
stays, tagged fitted/peeked as before.
