## The two discoveries that cost the most time
1. **Strike-arm anchoring is one tick too late.** The first implementation armed the countdown in the `Update::Strike { charged }` arm; the row did not move. Marker-debug (BUSTER_FX pushes at (120,30)) showed the Strike arm fires exactly once at capture f222..224 = row k=7 — one tick AFTER canon's flash first frame (k=6). Canon's flash object appears 6 ticks into the charged attack state, BEFORE the strike event on our compressed pose timeline. Fix: arm at the release (`attack_charged()`), not the strike. (Tried first: ChargeShotHandlersByTransformation_80117D4 cell 0x11 `sub_8011CB4` -> `useChipRelated_80127C0` chase to find canon's OAM writer; dead end for spawn semantics, a literal 0x082f7714 -> sheet frame record at ROM 0x82f34 remains unidentified; the OAM/VRAM watch made the writer question moot.)
2. **Delay calibration.** Delay is release-anchored: delay 2 put the flash's first OAM at row k=0; **delay 8** puts it at k=6..30 = canon f136..160 exactly (our release-to-OAM pipeline is 2 ticks longer than canon's; the countdown block runs after the arm point in the same tick, hence 8 not 6).
