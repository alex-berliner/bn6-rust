## Step 1+3: Rust table + named puts (src/battle.rs), wrapper word stores + compile-time bound (src/main.rs)

- `ORACLE_LAYOUT: [(&str, usize, usize); 19]` at module scope in src/battle.rs: the
  16 written fields PLUS mm_gap (17,1), enemy_gap (27,1) and padding (34,6) as entries,
  so the table tiles the whole 40 and the compile-time check is a full-tiling check:
  `oracle_layout_tiles` (const fn, cursor walk) + `const ORACLE_LAYOUT_OK: () = assert!(...)`
  -- cannot fold away, a bad edit fails the build.
- `OracleField` enum (discriminant = table index), `put_oracle`/`put_oracle_u8/16/32`
  named puts; oracle_snapshot rewritten with one named put per field, zero `b[` left
  (grep-verified). Gap/pad entries are listed but never written (b starts zeroed).
- main.rs `BattleMarker::put_bytes` now does word-wide volatile stores when the transfer
  is word-aligned (offset%4==0 && len%4==0): restores the single-`str` stores for the
  marker words at 0/4 (Q3 verifier note 1) and gives the 40/64-byte block writes word
  stores too. Still ONE unsafe block in the file. Runtime `assert!` kept as backstop
  (Q3 measured it cheaper than debug_assert), but the load-bearing bound is now the
  compile-time `ORACLE_REGION_FITS` const assert in main.rs
  (`ORACLE_OFFSET + ORACLE_SNAPSHOT_LEN <= BattleMarker::LEN`), twin of the tiling
  check (Q3 verifier note 2).
- ORACLE_SNAPSHOT_LEN made pub(crate) for that bound.

## Step 2: Python readers read the table (tools/oracle_layout.py, docs/oracle_layout.json, oracle.py, trace.py, harness.py)

- tools/oracle_layout.py (new): parses src/battle.rs's ORACLE_LAYOUT (regex, plus
  ORACLE_SNAPSHOT_LEN for the bound -- no second copy of 40) into docs/oracle_layout.json;
  re-runs the same tiling check in Python so a bad table fails loudly on both sides.
- docs/oracle_layout.json: generated, committed. AUTHORITY: src/battle.rs's ORACLE_TABLE
  is authoritative; the JSON is its projection, and harness.py's startup self-check
  (oracle_layout.self_check) regenerates the parse, diffs the JSON, and cross-checks
  oracle.py's reader offsets/block addr/len -- stale JSON or a drifted reader refuses
  to measure. One line in FIXTURE.md says the same for readers of the doc.
- tools/oracle.py: rust_fields' 17 hardcoded offsets -> ORCL_OFFSETS from the JSON;
  ORCL_BLOCK_LEN exported. Values proven identical: rust_fields on HEAD's own final
  dump reads state 4 action 8 anim 0 panel (2,2) hp 0x3c, enemy state 4 anim 0 panel
  (5,2) hp 0xffff sentinel, rng 0x499c1a92, battle_frame 0x1f, gauge 0 (all match the
  baseline bytes byte-for-byte).
- tools/trace.py: ORCL_ADDR from oracle.MM_ORACLE_ADDR, ORCL_LEN = ORACLE_BLOCK_LEN
  (40, same value, now derived).
- tools/harness.py: main() runs oracle_layout.self_check() before any row.

## Ideas tried and dropped
- Writing the named puts straight through BattleMarker (volatile per field): dropped --
  keeps the export-only local-array shape and main.rs's single volatile path; neutrality
  is then structural, not measured-only. put_bytes' word-aligned branch gives the block
  writes word stores anyway.
- Generating the JSON from a build.rs: dropped -- a committed projection + self-check is
  inspectable and needs no build machinery in a no_std bin.
