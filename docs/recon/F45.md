## 1. The plumbing — what holds per-Side flags, and what a ticket must change

* `--only-bg` is **not** a harness CLI flag. argparse at `tools/harness.py:3211-3216` accepts only
  `--only/--list/--no-gallery/--ui`. It is a raw passthrough to the capture binary:
  `tools/mgba_capture.c:530-553` (`--only-bg <n>` → `disableBG[b]=(b!=only)`; also forces
  `disableWIN[0/1]=true`).
* The per-Side arg bag is **`Side.extra: Tuple[str,...]`**, `tools/harness.py:315`, documented at
  `:292-293`; `Side.args()` appends it at **`:343`** (`a += list(self.extra)`), and
  `Side.do_capture` passes `args` to `cc.capture` at `:350-358`.
* The `field` row: **`Check(name="field", ui="both", frames=40, ...)` `tools/harness.py:1964-1997`**.
  rust Side `:1995` = `extra=() if ui=="integrated" else ("--disable-bg",)`; canon
  `_zero_enemy_canon("Start@10")` `:1996` -> `tools/harness.py:1576-1582`
  (`Side(rom=STERILE, loadstate=PAUSED, cheats=DELETE_ENEMY, script=..., extra=() if integrated else ("--disable-bg",))`).
  **No `--only-bg` anywhere on this row.** (`wave`, `tools/harness.py:2196-2211`, uses `--only-bg 2`
  on `FIELD_ROW`, but that is a DIFFERENT fixture — STERILE+PAUSED+ALIVE, enemy present — not this row.)
* To change it: add **new Check row(s)** whose rust and canon `Side.extra` carry `("--only-bg","N")`.
  Nothing in the field row itself can be asked for a per-layer split.

### Can a same-content mask be built WITHOUT the renumbering? — yes, but split at the boundary

There is **no** blank-to-fixed-colour flag and **no** renderer per-layer pixel dump:
`--only-bg-with-obj` (`mgba_capture.c:532`) still drops the other three BGs via the same
`disableBG[b]=(b!=only)` `:546-547`; `--disable-obj` (`:535`) keeps all four; `--disable-bg`
(`:386-398`) drops all BGs and both WINs. The only non-renderer escape is memory dumping,
`--dump addr:bytes:file` (`mgba_capture.c:1025-1053`, reads system memory — OAM at 0x07000000,
RenderInfo BGxCNT/HOFS shadows 0x0200ac4c.., `eGFXAnimStates` 0x020094c0) — a new capture shape,
not a flag.

**But the renumbering is per-frame and one-sided, so it can be COMPENSATED with static per-Side
indices, provided the compared window sits entirely on one side of the boundary.** See §2 for the
boundary: rust capture 121 = battle 110 = k=5. So:

* pre-boundary window: rust and canon use the **same** `--only-bg N`.
* post-boundary window: rust layout has shifted down one hardware BG, so pair
  **canon `--only-bg N` with rust `--only-bg N-1`**.

A newest-ticket recipe (no src change, no allowlist change):
```
pre  row: Align(canon_ref=130, rust_offset=108, search=None), frames=5   # rust 116..120 ↔ canon 130..134
          rust extra=("--only-bg",N), canon extra=("--only-bg",N)
post row: Align(canon_ref=135, rust_offset=113, search=None), frames=40  # rust 121..160 ↔ canon 135..174
          rust extra=("--only-bg",N-1), canon extra=("--only-bg",N)
```
Use `search=None` + the event-locked offset (F33c) — a 5-frame window cannot support the search,
and the post row's offset is just 108+5.

UNVERIFIED: that "canon N ↔ rust N-1" really is same content. It follows from `.show()` order
(§2) + the harness's own note (`tools/harness.py:1362-1370`), NOT from a capture. Cheapest kill:
run the post row for N=1 and watch the BG1-only diff **collapse** from 100% saturated (F42's
`--only-bg 1` on both sides) to a small per-frame number; a still-saturated result kills the pairing.
If it collapses, F45 is a PARITY ticket (new rows only). If it does not, F45 is a TOOLING ticket
(needs a non-renumbering layer isolation).

**Rule for any worker before trusting a per-layer number.** For each per-layer isolation capture,
report, per frame and **per side**, the differing-pixel count and its coverage (mask/38400). A frame
whose isolation mask covers **> X** of the screen is not a layer mask, it is a full-screen render —
drop it, never average over it. Take **X = 75%**: it sits in the measured gap (28.9%, 92.5%) between
the usable frames and the saturated ones. This is necessary, not sufficient — coverage cannot prove
the two sides isolated the *same* content; the index compensation (§1) must be argued per frame from
`.show()` order. Also state the usable-window px share so a reader knows how much of the row is left.

## 6. Single most likely mechanism — UNVERIFIED

* k=2,3,4 are rust captures **118,119,120**, the three byte-identical **stall** frames
  (`tools/harness.py:1362-1364`). On those frames BG1-only reads 7362/11117/11117 while integrated
  reads only 3566/5319/5319 — i.e. the arena hides most of BG1, so the honest pre-boundary residue
  is **backdrop (BG1) content**, carried by the 3-frame backdrop freeze. (UNVERIFIED: it could be a
  content wrong-tile at the same phase.)
* k>=5 is real residue (2.5–5.6k/frame, k=5 boundary = capture 121 = `shown` Some) but its carrier
  is **UNMEASURED**; F42's BG1-only mask there is a full-screen render (§3).
* Most likely mechanism, UNVERIFIED: **the end-sequence offset (F32)** — rust's backdrop/window
  transition fires ~3 frames early (freeze at 118-120) and renumbers the hardware layers from 121,
  so the composite diverges for the rest of the window. It is a TIMING/LAYOUT story, not a
  per-layer tile-art divergence. Counter-evidence to keep: F42's integer shift test at k=5/20/32
  found (0,0) the unique minimum (`docs/worklog/F42.md`), which rules out a pure scroll-phase offset.
* Cheapest kill-checks: `--watch`/`--peek eGFXAnimStates[0]` (0x020094c0, entry word + `Timer`) and
  `eBGScrollCBCounters` (0x02009690) on BOTH sides across rust 116..125 / canon 130..139 — a rust
  value that stops at 118-120 confirms the freeze; `--watch` RenderInfo BGxCNT/HOFS shadows
  (0x0200ac4c..) on the rust side to see the layer renumber at capture 121 (F42's own "what next").

## 7. Headline

Per-layer attribution IS possible with the **existing** capture tooling, but not from the existing
`field` row and not through one 40-frame window: the hardware layers renumber on the rust side at
capture 121 (=k=5), so the window must be split at that boundary and the post-boundary rows must pair
`canon --only-bg N` with `rust --only-bg N-1` (§1). No blank-to-colour flag and no renderer per-layer
dump exist; the only non-renumbering escape is a memory dump (`--dump`). Therefore **F45 = new-row
(parity) ticket**, gated on the 6-capture first pass in §5, with §3's saturation rule applied before
any per-layer number is believed. If that first pass does not collapse the BG1-only saturation, the
compensation is wrong and F45 collapses to a **tooling ticket** (add a non-renumbering layer
isolation). Either way, the k>=5 residue's carrier is currently UNMEASURED and no per-layer claim on
it can be carried forward from F42.
