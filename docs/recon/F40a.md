**The measured contradiction and the free branch witness.** `0x020352a0 == 0` puts `sub_801C4E4`
in `loc_801C534`: the "empty" bar is **16 cells of tile 0x9222** (its own artwork, not black) plus
one 0x9222 at j=7; the full bar is 0x9232+(t&3). So a zero gauge and a "visually full" bar are
compatible *if the observed pixels are 0x9222*. The +0x00 counter at **0x02035280** is the cheapest
witness: it is incremented **only** in the >= 0x4000 branch (`asm00_2.s:26387-26394`), so
`--peek 0x02035280` == 0 through the capture means canon took the NOT-FULL branch.

Battle-start init that touches the same struct: `sub_801DF0C` (`asm00_2.s:~29780-29833`) zeroes
+0x18/+0x19 and queues GFX; `sub_801DF32` (`asm00_2.s:29836-29874`) calls `ClearCustGauge` then
queues `dword_86E1C78 -> byte_3001B00, 0x20`; `ClearCustGauge` callers also at `asm00_2.s:29788,
29803, 29818, 29838` (same routine group), `asm03_0.s:540, 3383`. So canon's own battle-start /
window path *clears* the gauge. `SetCustGauge` callers (unread this pass): `asm00_1.s:11767, 11807,
12313, 13628, 17289`, `asm03_0.s:16397`, `asm32.s:16117, 16315`; `sub_801DFB8` callers
`asm00_1.s:11234`, `asm31.s:89444`; `sub_801DFB8` is the writer `src/battle.rs:1657` attributes
to "asm00_2.s:29892-29907" -- **that cite is stale**: 29892-29907 is the comment tail +
`ClearCustGauge`'s head; `sub_801DFB8` is `asm00_2.s:29931-29947`.

**Candidate mechanism (unverified):** the bar is not gauge-full at all; canon is drawing its
not-full 0x9222 interior, and the k>=6 ~2047/frame BG3 residue is a *tile choice / map placement*
difference in our `set_gauge` (`src/hudtiles.rs:300-395`, body cells `full_state=None` ->

## B. The chip-window auto-open

Rust side, `src/battle.rs:1995-2006` (the comment is 1995-2001; **:1998 is exactly the frame-165
sentence**, so T9l's cite is the precise one and docs/worklog/T9l.md:38's ":1990-2006" is the
enclosing block, starting three lines early at the `for enemy` loop):
```
        // A BATTLE OPENS WITH THE CHIP WINDOW. Measured on the real ROM from a
        // save state at a battle's first frame: the field fades in, the
        // viruses materialise, and the window comes up on its own at frame
        // 165 with nothing pressed. This build used to start the gauge
        // empty in a release build, which is 0x4000 / 0xd = 1260 frames -- twenty-one
        // seconds of an unarmed navi before the first chip. The gauge starts
        // FULL, and the pause that follows it opens the window.
        let gauge = match fixture {
            Some(f) => if f.gauge != 0 { GAUGE_FULL } else { 0 },
            None => GAUGE_FULL,
        };
        let gauge_pause = 0u16;
```
Counter that decides it: `gauge_pause` (declared `src/battle.rs:1507`), armed `src/battle.rs:2752-2753`
```
                if self.gauge == GAUGE_FULL && self.open_window_allowed() {
                    self.gauge_pause = GAUGE_PAUSE;
```
decremented `:2648`, paused predicate `:2810`; the gauge itself steps at `:2734`
`self.gauge = (self.gauge + GAUGE_STEP).min(GAUGE_FULL);` and the window-open branch is `:2643`
(`} else if self.gauge_pause > 0 && self.open_window_allowed() {`); `GAUGE_FULL = 0x4000` at
`:1115`.

Canon counterpart of the predicate is `asm00_1.s:~15264-15288`, `sub_800A21C` (file comment at

Neighbours: `sub_800A1D0` (`asm00_1.s:~15233-15262`) returns 1 on `battle_getFlags` bits 2 or 0x10

**Interaction (unverified).** If canon's gauge really is 0 (A's measurement) then `sub_800A21C`
returns 0 and the pause/window is NOT gauge-driven in this battle -- the ladder "gauge full ->
pause -> window" (src/battle.rs:1995-2001, src/custom.rs:1) would be wrong for this row, and T9l's
lever "`gauge=1` should make our window open on canon's schedule" (docs/worklog/T9l.md:47-49) is
refuted. If instead the gauge fills to 0x4000 in the ~150 frames before 165, the ladder holds and
the peek simply missed the pre-window window (the gauge group is cleared again on window open,
`ClearCustGauge` callers above).

**Cheapest check (B):** one no-poke capture watching `0x0203ca70:4` + `0x020352a0:2` +
`0x02035280:1` for frames 0..200. Self-transition to 0x04xxxxxx near 165 with `0x020352a0` 0 all
along => not gauge-driven; a 0x4000 ramp ending near 165 => gauge-driven and T9l's lever stands.

screen while OBJ mean ramps 93->12. The struct file for it exists --

read it, so the field name and the routine are unestablished here. REG_MOSAIC is 0x0400004c.

**Counter/register to watch (C):** `--watch 0x04000050:2,0x04000052:2,0x0400004c:2` during capture
