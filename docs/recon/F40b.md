## Q1 — the gauge word, re-read from bytes already on disk (no capture)

Bins: `/tmp/bn-92e9dcc8/probe_1298192_w_{020352a0,020352a2,0203ca70,0203ab68,0203ab80}.bin`
(a single 700-frame run; `tools/probe.py:84-87` deletes each watch bin after printing, so T9l's
170-frame peek is gone, and no `0x02035280` bin exists anywhere under /tmp).

| word | series |
|---|---|
| `0x020352a0` (gauge, `eStruct2035280+0x20`) | **0x0000 in every one of the 700 frames** — never ramps, never reaches 0x4000 |
| `0x020352a2` | constant 0x0020 |
| `0x0203ca70` (sequencer) | `0x00000000` for frames 0..165, then `0x04000000` from 166 on — i.e. only byte 3 (`[r5,#3]`) flips to 4 while the state byte `[r5]` stays 0x00 all run |

So T9l's prose "canon's gauge register reads 0 all 170 peeked frames" is **confirmed from bytes** —
which refutes F40a's lever (a): GUNNER_ROW's borrowed `gauge=0` is *not* diverging from a canon gauge
that fills. The `0x02035280` frames-standing-full witness was never recoverable (no bin on disk).
Caveat the recon states itself: bin row ↔ canon frame is unverified, and `[r5]` never taking the
window-opening values 0x20/0x24 means this 700-frame run may not be the row's window scenario at all
(or the address is aliased). That is the first thing a retry must settle.

## Q2 — what canon actually gates the window on

`SetWindowScreenFlag` / `sub_801B244` / `ClearBattleWindowFlag` **do not exist in canon's asm** —
they are our names. `battle_setFlags` bit 0x02 is set only by the gauge-full ladder
`sub_801C4AE` (asm00_2.s:26351-26361: `mul` by 0x4000, `cmp r0,#0x4000`, `bne` out, `mov r0,#2;
bl battle_setFlags`) — with the gauge measured at 0, that branch cannot be what opens this row's
window. The chain the recon names instead (all unverified):

- `stepBannerSequencer_800801C` (asm00_1.s:10448) indexes `BannerSequencerStates_8008038` by
  `[r5] = 0x0203ca70`; 0x08 = `bannerSeqState08Fight_80080D2` (:10585), 0x20 =
  `bannerSeqState20WindowOpening_8008452` (:11055), 0x24 = `bannerSeqState24WindowOpen_8008492`
  (:11087). (F40a's cites asm00_1.s:10422/10617 are stale by ~26/11 lines.)
- Inside FIGHT (:10669-10683): `bl sub_800A8F8; cmp 0; bl sub_800A1D0; beq out; b loc_800819A`
  where `loc_800819A` is `bl PauseBattle; mov r0,#0x20; str r0,[r5]`.
- `sub_800A1D0` (asm00_1.s:15260-15300) — the non-gauge predicate: `battle_isTimeStop`==0,
  `battle_isBattleOver`==0, then `GetBattleNaviStatsByte(player, 0x2c) ∈ {0x17,0x18}` for either
  player, **or** `battle_getFlags() & 0x02`, **or** `& 0x10`. A state-byte compare, no frame counter.
- The only timer-shaped thing on this path is BANNER_WAIT's `[r5+8] = 0x1e` (30) armed at
  asm00_1.s:10517-10534, whose exit compare is `isBannerBusy_801E754 == 0` (:10535-10540) — which is
  T7x's objective, not this row's plateau.

**Cheapest checks a retry should run** (one capture): `--trace-pc` around asm00_1.s:10669-10683 to
see whether `sub_800A1D0` returns nonzero there, plus `--watch-write 0x0203ca70:4` looking for
byte 0 → 0x20/0x24 in the window rows; and re-establish the bin-row ↔ capture-frame mapping that made
