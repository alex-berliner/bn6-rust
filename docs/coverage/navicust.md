# NaviCust battle effects (M7) — T110 enumeration + route measurement

Ticket T110 (branch `wt/t110`): enumerate the battle-effect handlers of
`navicust_jt_NCPs` (asm/asm37_0.s:2111) and start the M1 scenario rows. The
rows did NOT get built — the ticket's poke mechanism is refuted on the
battlestart route (measured, below). What landed: the full 47-handler
enumeration with per-handler cites (`docs/inventory/navicust_handlers.json`,
generated by `tools/inventory.py parse_navicust_handlers`), the measured
counts, and the route evidence the next pass needs.

## The 47 handlers (cites: reference/bn6f/asm/asm37_0.s)

Jump table `navicust_jt_NCPs` = 47 `.word` entries, lines 2112–2158, stride 4;
entry k's target label is cited per row below. All `Set`/`Get` calls are
`SetCurPETNaviStatsByte(0, slot, val)` / `GetCurPETNaviStatsByte(0, slot)`
(asm/asm00_2.s:10373/10389; slot indexes are `NaviStats.inc` offsets;
`oNaviStats_Size` = 0x64).

Counts (measured, supersedes the ticket's "19"):

- 47 entries = 1 no-op stub (`sub_813C808`, asm37_0.s:2162) + 46 handlers.
- **24 handlers are battle-relevant** (write ≥1 of the 19 NaviStats slots the
  SCOPE M7 section lists) over **13 distinct slots**: Attack 0x1, Speed 0x2,
  Charge 0x3, FstBarr 0x6, BLeftAbility 0x7, CustomLevel 0xa, MegaLevel 0xb,
  GigaLevel 0xc, FloatShoes 0x1b, AirShoes 0x1c, UnderShirt 0x1d,
  SuperArmor 0x23, SlipRun 0x35.
- **6 of the 19 slots have NO handler**: BButton 0x4, BPwrAtk 0x5, Mood 0xe,
  CustHPBug 0x19, EmotionBug 0x24, ProcessingBug 0x31.
- The other **22 handlers write 11 slots NOT in the 19**: 0xd (Rush/Beat/
  Tango), 0x1e (SneakRun), 0x1f (BugStop), 0x25 (Humor), 0x26 (Collect),
  0x27 (OilBody/Fish/Battery/Jungle), 0x33 (Millions), 0x36 (AutoHeal),
  0x5f (Poem), 0x60 (ChpShufl), 0x61 (NumbrOpn) — plus the 6 HPPlus
  handlers, which bypass SetCurPETNaviStatsByte entirely (direct `r10`
  writes, asm37_0.s:2704–2780).
- The published denominator **19 is a slot count, not a handler count**
  (it is `tools/inventory.py`'s `NAVICUST_FIELDS` list with `ChipRecovery`
  dropped because the parse regex matches `u8` only and ChipRecovery is
  `u16`). Restating SCOPE's M1 navicust denominator (19 slots vs 24
  battle-relevant handlers vs 47 entries) is left to the human; the slot
  table and the 0/19 line are unchanged on this branch.

Full per-handler table: `docs/inventory/navicust_handlers.json`
(index, handler symbol, `asm37_0.s:<label line> (jt entry <2112+k>)`,
effect, slot written, battle_relevant). The composed handlers call other
handlers directly: BodyPack → SuperArmor+FlotShoe+AirShoes+UnderSht
(asm37_0.s:2535), FldrPak1/2 → MegFldr1/2+Custom1/2 (:2545/:2553);
BustPack bumps slots 1/2/3 by +3 capped at 4 (:2496).

## Route measurement (canon `/tmp/bn6f_real.gba`, `battlestart.state`, 6 captures)

The ticket's scenario shape — `battlestart.state` + `--poke` of the
equipped-NCP channel — cannot light a battle-effect row on this route:

1. `--peek 0x02009424` (toolkit 0x020093b0 + 0x74 `NaviStatsPtr`) at frame 5
   reads **0x020047cc** — the live NaviStats record.
2. The record's own bytes at battlestart: CustomLevel(0xa)=4, MegaLevel(0xb)=5,
   GigaLevel(0xc)=5, BLeftAbility(7)=0xff, everything else battle-side 0 —
   the handlers already ran before this state was saved (they run from
   `reloadCurNaviStatBoosts_813c3ac`, whose callers are all map/boot/
   cutscene sites: asm00_1.s:4258/4569 (`cbGameState_80050EC`) and
   `sub_8005524`, cutscene scripts, asm28_0/33/36/asm03_1_0 — none is
   battle init).
3. The dispatch INPUT is inert at battlestart: program-record array at
   0x02004190 (confirmed: `--peek 0x0200940c` = r10[0x5c
   `Unk2004190_Ptr`] reads 0x02004190) is zeroed with halfword[0]=0 for
   every record → even if `applyNavicustPrograms_813C684` re-ran, every
   program would dispatch entry 0 (the stub).
4. Load-time poke of the record's FstBarr byte (`--poke 0x020047d2:0x0001`,
   slot 0x6 → 1) vs no-poke, 40 frames: **total 0 differing pixels** — the
   battle window never reads the map record either (battle copies
   eBattleNaviStats203F4AC read 0x0 at frames 5 and 40;
   `battle_copyStructsIncludingBattleStats_800b2d8` asm00_1.s:17812 copies
   FROM 0x0203F4AC outward, and no in-window writer of it was found).

Consequence: neither poke shape ((a) equipped-NCP channel, (b) stat-byte
poke) can produce a non-blind battle-effect row on the battlestart route.
Per the supervisor's decisions the rows were deliberately NOT built
(a BLIND-by-construction row is worse than none); the no-op stub is kept
as this control record only.
